# Сервер EV8 Ops — как поднять и как обслуживать

Дата: 28.09.2026. Устройство — как у Self Platform (`practices.md` §2, ТЗ v1.1
«тот же стек, чтобы не поддерживать два набора инструментов»): один сервер,
один Caddy на входе, два compose-проекта рядом.

```
        :80 :443
           │
       ┌───▼────┐  ev8-edge (свой compose-проект, свои сертификаты)
       │ Caddy  │
       └───┬────┘
           │ 127.0.0.1
     ┌─────┴──────┬──────────────┐
  :5173         :5174
┌────▼─────┐  ┌───▼──────┐        у каждого свои db · api · worker · web,
│ ev8-prod │  │ ev8-test │        свой том, своя база, свой .env
│  (тег)   │  │(develop) │
└──────────┘  └──────────┘
```

Наружу смотрит только Caddy. У стеков нет ни одного порта на публичном
интерфейсе: web слушает `127.0.0.1`, база и API — вообще ничего.

**Сервер:** `204.168.149.105`, Ubuntu 26.04, 2 ядра, 3.8 ГБ, 75 ГБ. Docker
установлен 28.09.

---

## Чем серверный стек отличается от ноутбучного

`docker-compose.yml` — это ноутбук. `docker-compose.prod.yml` — **отдельный
файл**, а не набор переопределений, потому что отличия не объявляют о себе:

| | ноутбук | сервер |
|---|---|---|
| Postgres | опубликован на 5433 | не опубликован вовсе |
| API | опубликован на 8082 | не опубликован; доступен через web |
| web | `vite preview` — дев-сервер | Caddy отдаёт собранный бандл |
| секрет сессии | принимается отладочный | слабый секрет останавливает запуск |
| демо-набор | можно включить | невозможен: `SEED_MODE` пуст |
| пропущенная переменная | молча подставится умолчание | compose не стартует и называет её |

## Установка, по шагам

### 1. Код на сервере

```bash
ssh root@204.168.149.105
git clone https://github.com/mkodzya/ev8-ops.git /srv/ev8-ops && cd /srv/ev8-ops
```

### 2. Вход

```bash
docker compose -p ev8-edge -f docker-compose.edge.yml up -d
```

Проверка: `curl -I http://ops.ev8.ge` отвечает перенаправлением на https. Если
нет — A-запись ещё не разошлась; сначала DNS, потом всё остальное.

Через тот же вход отдаются макеты нового сайта ev8.ge:
`https://test.ops.ev8.ge/garage/` — статичные страницы из
`/srv/ev8-site-preview/www/` на сервере, вне этого репозитория (Mika,
01.10.2026). Вход по логину `ev8`; пароль задаёт Mika:

```bash
ssh -t root@204.168.149.105 /srv/ev8-ops/deploy/set-site-password.sh
```

`--lock` ставит пароль, которого никто не знает. Перезапуск входа
(`docker compose -p ev8-edge -f docker-compose.edge.yml up -d`) на несколько
секунд закрывает и прод — только по слову Mika.

### 3. Тестовый стенд (`develop`)

```bash
cp .env.prod.example .env.test     # WEB_PORT=5174, свои секреты
docker compose -p ev8-test --env-file .env.test -f docker-compose.prod.yml up -d --build
```

### 4. Прод (тег)

```bash
git fetch --tags && git checkout 1.0.0
cp .env.prod.example .env.prod
docker compose -p ev8-prod --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

Первый запуск сам накатит миграции и заведёт владельца из `OWNER_EMAIL` и
`OWNER_PASSWORD` — только на пустой базе. Проверка:
`https://ops.ev8.ge/api/health` → `{"ok":true}`.

Прод собирается только по тегу на `main` (`practices.md` §2). Пока это правило
держит человек.

### 5. Копии

```bash
crontab -e
# каждый день в 04:10 по Тбилиси
10 4 * * * cd /srv/ev8-ops && BACKUP_DIR=/srv/ev8-backups deploy/backup.sh ev8-prod >> /var/log/ev8-backup.log 2>&1
```

`backup.sh` не просто снимает дамп: он восстанавливает его в одноразовую базу и
считает строки. Файл, который не восстановился, копией не считается и роняет
задание с ошибкой в лог.

**Раз в месяц руками:** свежий дамп на внешний диск, вне сервера и вне облака,
которое синхронизируется само. В дампе живые имена, телефоны и личные номера.

### 6. Тест и прод — как в Self Platform

Порядок работы тот же, что в Self Platform (решение Mika, 28.09.2026). В
`develop` вливают двое (Mika и Kardu); **после слияния сессия Mika сразу
выкатывает `develop` на test.ops.ev8.ge**:

```bash
ssh root@204.168.149.105 /srv/ev8-ops/deploy/follow-develop.sh --now
```

Скрипт подтягивает `develop` и пересобирает стек `ev8-test` с `nice`, если
то, что работает на стенде, отстаёт (последняя удачная сборка записана в
`/srv/ev8-test.deployed`). Сборка упала — стенд остаётся на прежнем, в ответе
хвост лога. Две сборки разом не пойдут: скрипт держит замок. Прод не трогает.
Без `--now` скрипт ничего не делает; строку cron, оставшуюся с нескольких
часов автообновления 28.09, `--now` убирает сам.

Что было — `tail /var/log/ev8-follow.log`: строка на каждую выкатку, с
коммитом, на котором теперь стенд.

**Прод — только по слову Mika.** Тогда сессия Mika выпускает релиз (ветка
`release/X.Y.Z`, версии, `main` с аннотированным тегом, обратно в `develop`)
и выкатывает его:

```bash
ssh root@204.168.149.105 /srv/ev8-ops/deploy/deploy-prod.sh X.Y.Z
```

`deploy/deploy-prod.sh` берёт только тег, который есть на `main`. Сначала
снимает копию прод-базы с той же проверкой восстановления, что и ночная;
копия не восстановилась — релиз не идёт, прод не тронут. Потом переключает
`/srv/ev8-prod` на тег и пересобирает стек `ev8-prod`. Сборка упала — в
ответе хвост лога и команда отката на прежний тег. Журнал релизов —
`/var/log/ev8-release.log`. Скрипт лежит в тестовой копии (`/srv/ev8-ops`),
но работает только с `/srv/ev8-prod`.

## Что проверить в первый день

1. `https://ops.ev8.ge/api/health` → `{"ok":true}`, сертификат валиден, http
   перенаправляет на https.
2. `docker compose -p ev8-prod ps` — четыре контейнера, `db` и `api` healthy.
3. Наружу ничего, кроме 80 и 443: `ss -tlnp | grep -v 127.0.0.1`.
4. Демо-вход отказан: `curl -X POST https://ops.ev8.ge/api/auth/login -H
   'content-type: application/json' -d '{"email":"demo.director@ev8.test","password":"x"}'`
   → 403.
5. Вход владельца работает; после первого входа сменить пароль в «Мой вход» и
   очистить `OWNER_PASSWORD` в `.env.prod`.
6. `deploy/backup.sh ev8-prod` — прошёл и написал «restored».

## Забытый пароль

Пароль в базе не лежит: лежит односторонний слепок, из которого пароль не
восстанавливается. Забытый пароль поэтому не вспоминают, а заменяют:

```
/srv/set-password.sh ev8-prod .env.prod mika@selfstudio.se
```

Скрипт (`deploy/set-password.sh`, на сервере лежит копия в `/srv`) спрашивает
новый пароль дважды и не показывает его при наборе. Пароль уходит в контейнер
по стандартному вводу и возвращается уже слепком — в историю команд, в список
процессов и в логи он не попадает. Старые сессии на других устройствах после
смены закрываются, счётчик неудачных попыток обнуляется.

Стенды независимы: у `ev8-prod` и `ev8-test` свои базы, пароль меняется на
каждом отдельно (для теста — `ev8-test` и `.env.test`, из `/srv/ev8-ops`).

## Заявка с сайта на почту

Новый сайт (`mkodzya/ev8-site`) может отправлять заявку в очередь не в WhatsApp, а
письмом: `POST /api/site/queue` (имя, телефон, текст заявки) → письмо на ящик
компании. В базу и в логи заявка не пишется. Пока почта не настроена, адрес отвечает
503, и сайт должен оставить кнопку WhatsApp. Попросил Kardu 06.10.2026; решение —
п. 71 реестра книги.

Включает Mika, на каждом стенде отдельно (`.env.test`, `.env.prod`):

```
SITE_MAIL_HOST=…              # сервер исходящей почты ящика
SITE_MAIL_PORT=465            # 465 — TLS сразу; 587 — STARTTLS
SITE_MAIL_USER=info@ev8.ge
SITE_MAIL_PASSWORD=…          # пароль приложения, не пароль ящика
SITE_MAIL_TO=                 # пусто — письмо уходит в тот же ящик
```

- **Пароль — только пароль приложения**, созданный для этого: он умеет только
  отправлять почту и отзывается отдельно. Пароль самого ящика открывает Drive и всю
  почту — на сервер он не кладётся.
- На каком сервисе ящик info@ev8.ge и какой у него сервер исходящей почты — в книге
  нет данных. Если это Google Workspace — `smtp.gmail.com`, порт 465, пароль
  приложения — в настройках безопасности аккаунта (нужна двухэтапная проверка).
- После правки `.env` — перезапуск стенда обычным путём (`follow-develop.sh --now`
  для теста, `deploy-prod.sh` для прода).
- Проверка на тесте: заявка с предпросмотра сайта → письмо в ящике. Ответ 502 и
  строка `site queue mail not sent` в `docker compose logs api` — ящик не принял
  вход: неверный сервер, порт или пароль.
- Защита от спама: скрытое поле для ботов, не больше трёх заявок с одного телефона
  и тридцати всего за час. Счётчик в памяти и сбрасывается при перезапуске.
- Для боевого сайта на ev8.ge вход должен отправлять его `/api/site/*` на прод-стек
  (`Caddyfile.edge`) — это делается вместе с запуском сайта.

## Когда что-то не так

- **Сертификат не выдаётся** — DNS не указывает на эту машину, или 80-й порт
  занят кем-то ещё. Caddy должен быть единственным, кто слушает 80 и 443.
- **Стек не поднимается с `variable is not set`** — в `.env` пустая строка. Это
  защита, а не ошибка.
- **Изменения не видны** — `--build`: web отдаёт собранный бандл, без пересборки
  остаётся прежний.
- **Откат** — `git checkout <предыдущий тег>` и та же команда запуска. История
  прода — список тегов.
