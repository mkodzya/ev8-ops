# Как проверяется каждое требование

Практики §3 (Nichebox §0.4, IEEE 29148): у требования есть метод проверки, и
приёмка этапа идёт по этим методам, а не по ощущению готовности.

| Метод | Что значит |
|---|---|
| **T** Test | Автотест. Падение теста = требование не выполнено. Прогон: `npm test`. |
| **D** Demonstration | Человек проходит сценарий на стенде и видит результат. Приёмщик назван. |
| **I** Inspection | Чтение кода, схемы или файла — там, где смотреть нужно на устройство, а не на поведение. |
| **A** Analysis | Расчёт или сверка с внешним источником до тетри. |

Колонка «Чем» — где лежит доказательство сегодня. «—» значит, что проверки нет
и это открытый долг, а не забытая строка.
