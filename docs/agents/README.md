# Редизайн EV8 Ops: три роли и один цикл

Задача — пересобрать продукт с точки зрения UX: как он устроен, выглядит и работает, исходя из бизнеса,
его процессов и плана развития. Вход — книга проекта, аудит `docs/audit/2026-09-audit.md` и ТЗ v2
`docs/spec/ev8-ops-tz-v2.md` (роль аналитика, который их написал, — в `archive/`).

Каждая роль — отдельная сессия Claude Code в папке `ev8-ops-platform`, запуск одной строкой:

> Прочитай `docs/agents/<роль>.md` и работай по нему.

| Роль | Файл | Сессия |
|---|---|---|
| Продуктовый дизайнер | `designer.md` | «EV8 · Дизайнер» (Opus, effort high) |
| Разработчик | `developer.md` | «EV8 · Разработчик» |
| Тестировщик | `tester.md` | «EV8 · Тестировщик» |

**Кто коммитит.** Дизайнер правит файлы в рабочей копии, но в git не пишет — коммитит разработчик
(один писатель на рабочую копию). Коммиты подписаны одним человеком, поэтому автора по `git log` не
отличить: нужно знать, кто сделал, — спросить сессию. Незакоммиченные `docs/redesign/*.md` в рабочей
копии — обычно дизайнер в работе; их не трогать и не коммитить за него.

## Цикл

```
ЭТАП А — схема продукта (один раз)
  Дизайнер: А1 люди и работа → А2 структура и волны ──► Mika: вопросы, решения
  Дизайнер: А3 дизайн-система → А4 прототипы ──► Mika: «утверждаю»
  Разработчик: build-plan.md ──► Mika: «план утверждён»

ЭТАП Б — волна N (5–6 раз)
  Дизайнер: wave-N.md + прототипы волны ──► Mika: «волна N утверждена»
  Разработчик: сборка на QA ──► docs/qa/wave-N-ready.md
  Тестировщик: сценарии + сверка с прототипом ──► docs/qa/wave-N-report.md
  Разработчик чинит (≤ 2 раундов) ⇄ тестировщик перепроверяет; вопросы к дизайну — дизайнеру
  Mika: смотрит волну на QA ──► «волна N принята» ──► разработчик убирает старое, handoff
```

Параллельно идёт только одно: **дизайнер готовит волну N+1, пока разработчик собирает волну N** — дизайнер
ничего не собирает и машину не нагружает. Разработчик и тестировщик никогда не работают одновременно
(Mac 8 ГБ).

## Что говорить

| Когда | Кому | Что сказать | Перед этим |
|---|---|---|---|
| Старт | Дизайнер | «Прочитай docs/agents/designer.md и работай по нему» | Войти в Chrome на http://127.0.0.1:5185 |
| После А2 | Дизайнер | ответы на вопросы, «продолжай» | прочитать сводку |
| После А4 | Дизайнер | правки или «утверждаю» | открыть `docs/redesign/prototypes/index.html` |
| Схема утверждена | Разработчик | «Прочитай docs/agents/developer.md. Схема утверждена, сделай план сборки» | — |
| План готов | Разработчик | «план утверждён» | прочитать `build-plan.md` |
| Волна N | Дизайнер | «Готовь волну N» | — |
| Прототипы волны | Разработчик | «Волна N утверждена, собирай» | посмотреть `wave-N.md` и прототипы |
| Волна собрана | Тестировщик | «Прочитай docs/agents/tester.md. Тестируй волну N» | Chrome на QA под нужной ролью |
| Отчёт | Разработчик | «Чини по docs/qa/wave-N-report.md» | — |
| Исправлено | Тестировщик | «Перепроверь волну N» | — |
| Нет блокеров | Разработчик | «Волна N принята» | посмотреть волну на QA |

Mika нужен в трёх местах: **схема** (после А2 и А4), **прототипы волны**, **приёмка волны**. Всё
остальное роли передают друг другу через файлы.

## Файлы

| Файл | Пишет | Что |
|---|---|---|
| `docs/redesign/blueprint.md` | дизайнер | люди и работа, структура, волны, дизайн-система |
| `docs/redesign/prototypes/` | дизайнер | статичные HTML-прототипы, `index.html` — оглавление |
| `docs/redesign/build-plan.md` | разработчик | как пересобирается продукт, волны, риски |
| `docs/redesign/wave-N.md` | дизайнер | экраны, сценарии, критерии приёмки волны |
| `docs/qa/wave-N-ready.md` | разработчик | что собрано, отклонения, раунды исправлений |
| `docs/qa/wave-N-report.md` | тестировщик | вердикт, баги, расхождения, вопросы к дизайну |
| `docs/design/ux.md`, `brand.md` | дизайнер | обновляются после «утверждаю» |

Стенды и QA — `docs/qa/README.md`.
