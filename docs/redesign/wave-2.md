# Волна 2 — деньги

Дата: 18.09.2026. Дизайнер. Основание: схема [`blueprint.md`](blueprint.md) (D4–D6, С2, С4), план сборки
[`build-plan.md`](build-plan.md) (волна 2, Р5), принципы [`ux.md`](../design/ux.md), волна 1

## 1. Цель

Деньги перестают теряться и задваиваться, и всё про деньги — в одном разделе: разобрать выписку, принять
или выдать деньги одной формой, увидеть платежи, кассу наличных по людям, выписки и залоги. Долг клиента —
одна цифра на всех экранах.

**Для Kardu (телефон):** «＋ → Принять деньги» с подсказанной суммой и тем, что закроет платёж; разбор
выписки по одной строке с причиной подсказки, без чужих привязок и дублей; касса: кто из менеджеров сдал
наличные, принять одной кнопкой; выдача залога — платёж с каналом.

**Для менеджеров:** «Принять наличные» из «＋», своя касса за день и «Сдал владельцу».

**Для Mika (ноутбук):** выписку можно загружать реже и не бояться: совпавшее с внесённым руками не
запишется второй раз, правила привязывают только по двум признакам, всё привязанное правилами можно
проверить и отвязать; платежи со знаком, фильтрами и итогом; свежесть выписок по банкам.

**Чего в волне нет.** Мастера выдачи и возврата — прежние до волны 3 (они вызывают новую форму денег, где
раньше была старая панель). Пересчёт себестоимости после доплаты поставщику — волна 5. Очередь «Сегодня» —
волна 4 (но цифра долга в ней уже та же).

## 3. Экраны и поведение

### 3.0 Раздел «Деньги» и точки входа

- **Вкладки** (в адресе `/money/…`): **Разобрать** (число строк) · **Платежи** · **Касса** (число ждущих
  приёма) · **Выписки** · **Залоги**. Открывается на «Разобрать», если там есть строки, иначе на
  «Платежи».
- **Менеджер** видит раздел как «Касса» на нижней панели: вкладки **Касса** · **Мои платежи**. Разобрать,
  Выписки и Залоги — нет (волна 1, права).
- **«＋»:** владелец — добавляется «Принять деньги» третьим пунктом (после «Выдать» и «Возврат»); менеджер —
  «Принять наличные» третьим.
- **Боковая панель ноутбука:** главное действие владельца становится «Принять деньги» (менеджер — «Выдать
  мопед», как было).
- **Карточки аренды, продажи, закупки, ремонта** — прежняя панель платежа заменяется кнопкой, которая
  открывает форму денег с подставленной записью.

### 3.1 Одна форма денег

Лист на телефоне, панель справа на ноутбуке. Ключ операции — с открытия (волна 1).

| Поле | Поведение |
|---|---|
| Направление | Приход / Расход. Менеджер — только приход, поля нет |
| От кого / кому | Поиск клиента, поставщика или записи (номер, имя, телефон). Выбранный клиент показывает свои долги по записям — одной цифрой и по строкам. Открытая из карточки — запись подставлена |
| Основание | Приход: аренда, залог, продажа (взнос), ремонт за счёт клиента, на счёт клиента. Расход: выдать залог, выкуп обратно, оплата поставщику. Определяется выбранной записью; меняется, только если у записи их несколько |
| Сумма | Подсказки чипами: долг; долг + следующая неделя (аренда); взнос (продажа); к выдаче (залог). Любая сумма вручную |
| Канал | Наличные · Карта · Перевод. **У прихода** «наличные» выбраны заранее — самый частый случай. **У расхода** (выдать залог, выкуп, оплата поставщику) канал **не выбран**: деньги уходят из кассы или со счёта, и это называют явно; без выбора записать нельзя (уточнено 21.09.2026). Менеджер — только наличные, поля нет |
| Карта | «Банк зачислит X; комиссия Y — расход компании»: нетто = брутто − 1,5 %, долг гасится по брутто (`money.md`). Для аренды и **продажи** одинаково (M12) |
| Перевод, внесённый вручную | Подсказка: «Строка выписки найдёт этот платёж сама» (сверка §3.2) |
| Дата | Сегодня. Владелец может указать прошлую дату — с причиной (ux №14). Менеджер — только сегодня |
| Закроет | Перед записью: что закроет платёж — залог, недели с датами, взнос N из M — и новое «оплачено по». Частичная оплата: сначала недовнесённый залог, потом недели (умолчание Q6, как сейчас). Больше долга — «лишнее N ₾ — на счёт клиента, уйдёт в следующую неделю» (`rental.md`) |
| Выдать залог | Сумма не больше «получено − удержано − выдано» (M7). Наличными больше, чем у выдающего на руках, — можно, с предупреждением «касса уйдёт в минус −M ₾» и подтверждением (уточнено 18.09.2026). «Кому»: плательщик по умолчанию; другой человек — по просьбе клиента, с причиной (`rental.md`); решает один владелец (D18) |
| Оплата поставщику | Ушло со счёта, GEL; это в валюте инвойса; комиссия банка (расход, в себестоимость не входит). Курс показывается, если введены обе суммы. Пересчёт себестоимости после доплаты — волна 5 |
| Выкуп обратно | Сумма и канал; после записи долг покупателя по этой продаже — 0 (M8; как закрывается остаток графика — умолчание Q20, волна 5) |
| Кнопка | «Записать 150 ₾» / «Выдать 180 ₾» — глагол и сумма. Четыре вида отправки (волна 1) |
| После записи | Сообщение «Записано 150 ₾ наличными» и **«Отменить» 10 с** — тот же человек, без причины, в журнал «отменено сразу». Позже — только «Аннулировать» у владельца (§3.3) |

### 3.2 Разобрать

Строки выписок, которые не привязались при загрузке. Фильтр: **Поступления** · **Списания**.

**Группы по порядку:**

1. **Похоже, уже записан** — есть платёж того же клиента или записи с той же суммой (брутто или нетто),
   датой в пределах ±3 календарных дней (умолчание Q2) и ещё без строки выписки. Один кандидат при загрузке
   связывается сам и сюда не попадает — **если нет другой записи с долгом на ту же сумму и подходящую дату**
   (иначе сюда, с обоими вариантами; уточнено 18.09.2026 по отчёту волны 2); сюда — когда кандидатов несколько или совпадение неполное. Действия:
   «Да, это он» (строка связывается с платежом, новый не создаётся) / «Нет, другой платёж».
2. **Подсказки** — порядок: клиент по имени плательщика (любые его аренды, продажи, ремонты с долгом, в том
   числе закрытые аренды) → сумма и дата → остальное (B2-05). У подсказки — **причина словами**: «Имя
   совпало: …, долг N по R-…», «Карта: 325,05 = 330 − 1,5 %, аренда выдана в этот день, имени нет». Первая
   подсказка — главной кнопкой «Привязать к R-…», вторая и дальше — тихими кнопками.
3. **Без подсказки** — сразу поле поиска записи.

**Действия у каждой строки:** «Другое» — поиск записи по номеру, имени, телефону; результат — записи
клиента с долгом и «На счёт клиента»; «⋯ → Это не наше» — строка уходит из очереди с обязательной
причиной.

**Взнос наличных** в поступлениях сверяется с записями «Внёс в банк» (§3.4).

**Списания:** сверка с оплатами поставщику и выдачами залога, внесёнными вручную (та же логика, что
«уже записан»). Остальное — «Расход компании» одним нажатием (расходы компании в системе не ведутся,
бухгалтерия — вне продукта, `money.md`).

**Двойной тап** — одна привязка: кнопка «Привязываем…», повтор не делает ничего; в базе строка связана не
больше чем с одним действующим платежом (B2-02). После привязки — «Привязано к R-… · Отменить» 10 с.

**Разобрано правилами** — ссылка внизу очереди: строки, привязанные при загрузке, с причиной; «Отвязать»
возвращает строку в очередь, платёж аннулируется (B2-07).

**Правила автопривязки при загрузке** (B2-04, ADR-0004):
- имя плательщика совпало с клиентом, у которого одна подходящая запись с долгом на эту сумму; **или**
- сумма совпала **и** дата строки — день выдачи аренды (типовые суммы эквайринга) либо в пределах недели,
  которую эта сумма закрывает;
- одной суммы без второго признака мало — только подсказка;
- аренды «спорная», «пауза», «бронь» не участвуют (умолчание Q25);
- «Wallet/domestic MC cards» — признак карты (B2-06; другие признаки — по образцу выписки, Q2-b).

**Состояния:** пусто — «Всё разобрано», свежесть выписок и «Разобрано правилами за неделю: N»; нет связи —
очередь из кэша, нажатие даёт «Не записалось — повторить».

**Ноутбук:** таблица строк и панель выбранной строки; клавиши: ↑↓ — строка, Enter — привязать к первой
подсказке, «/» — другая запись, N — «не наше».

### 3.3 Платежи

- **Карточка на телефоне:** кто (клиент или поставщик), основание словами и номер записи; справа — сумма
  **со знаком** (приход зелёным `accent-ink`, расход чёрным) и канал; у карты — «банк 325,05»; у связанного
  со строкой выписки — «выписка ✓».
- **Фильтры** (в адресе): период (эта неделя по умолчанию, неделя, месяц, свой), канал, направление,
  основание, кто внёс. **Итог** над списком: приход, расход, комиссия эквайринга.
- **Страница платежа** (нова): сумма, клиент, канал, банк зачислил и комиссия, дата, кто и когда внёс;
  «Закрыл» — распределение (залог, недели, взносы); строка выписки; журнал. Меню «⋯»: «Аннулировать» —
  только владелец, причина обязательна; недели и взносы снова становятся неоплаченными, строка выписки
  возвращается в «Разобрать», распределения остаются в журнале (B2-07).
- **Менеджер** — «Мои платежи»: свои платежи, без аннулирования.

### 3.4 Касса

Решение Mika В3 (`money.md` «Каналы денег»): касса по людям, менеджер «сдал», владелец «принял».

- **Владелец:** период (сегодня, неделя, свой). По каждому человеку: принято наличными (число и сумма),
  выдано наличными, сдал, принял владелец, расхождение, на руках. Менеджер сдал — «Принять N» или «Не
  сходится»: пересчитанная сумма и **обязательная причина**; расхождение остаётся за менеджером до разбора
  и видно в кассе и журнале. У владельца «на руках» = своё принятое − выданное + принятое от менеджеров.
- **Менеджер:** «На руках сегодня» крупно; список принятых наличных; кнопка «Сдал владельцу N» в липкой
  полосе. После сдачи — «ждёт владельца», новые наличные копятся отдельно.
- **Пусто:** «Сегодня наличных не было» и «Принять наличные».
- **Ноутбук:** таблица по людям за период.
- **Внёс в банк** (решение Mika 18.09.2026): у владельца в кассе кнопка «Внёс в банк N» — сумма (не больше
  «на руках»), банк, дата; расход из кассы владельца, не платёж клиента. Строка выписки «взнос наличных»
  находит эту запись сама по сумме и дате ±3 дня (как оплату поставщику) и связывается с ней; без записи —
  в «Разобрать → Поступления» с подсказкой «Похоже на внесение наличных — записать „Внёс в банк“?».

### 3.5 Выписки

- **По банку** (BOG, TBC, Credo): последняя загрузка, по какую дату; больше 7 дней — предупреждение
  (сигнал свежести, `docs/practices.md`; порог — предложение). Ниже — история загрузок: файл, период, кто,
  строк и разобрано.
- **Загрузить:** выбор файла → **предпросмотр до записи:** банк и период, новых и уже загруженных строк,
  поступлений и списаний; «совпало с внесёнными вручную», «привяжут правила», «уйдут в Разобрать» →
  «Загрузить N строк» → итог и «Разобрать N».
- **Ошибки до отправки:** файл больше предела (текст с пределом и советом «выгрузите период короче»,
  QA-1-05); не выписка BOG или TBC (какие файлы нужны); все строки уже загружены.

### 3.6 Залоги

- **Итог:** «На руках (получено)» = Σ (получено − удержано − выдано) — умолчание Q16; «начислено по
  договорам» — тихой строкой. Оба — по одному множеству: действующие аренды и возвращённые без решения;
  подпись «по N арендам» (уточнено 18.09.2026).
- **Сегменты:** На руках · **К выдаче** (решено вернуть, ещё не выдано) · **Недовнесён** (получено меньше,
  чем по договору) · Закрыты.
- **Карточка:** клиент, аренда, когда вернул и решение; справа — сумма; у «к выдаче» — кнопка «Выдать»
  (форма денег, расход, §3.1).
- Удержания строками (ремонт, возврат) — волна 3 (B5-04).

### 3.7 Одна цифра долга

Одна функция в `shared` (B7-02), одинаковая в «Сегодня», аренде, продаже, клиенте, поиске, форме денег.

- **Должен** = просроченное по арендам + просроченные взносы продаж + недовнесённый залог + неоплаченный
  ремонт за счёт клиента. Будущие взносы — отдельной строкой «Впереди по рассрочке» (умолчание Q21).
  *(12.10.2026: по арендам в цифре — каждая начавшаяся неоплаченная неделя, с её первого дня; так цифра
  считалась и раньше. Неделя, начавшаяся сегодня, в цифре есть, но просрочкой не названа: если вся цифра —
  такие деньги, она пишется «К оплате сегодня», чёрным. `due-today.md` §3.4, ADR-0017.)*
- **Залог на руках — не долг**, отдельной тихой строкой (`money.md`).
- Выкупленная обратно продажа долга не даёт (M8).
- **Вид:** «Должен N ₾» крупно; под ним — из чего сложено по записям; ниже тихо — впереди по рассрочке и
  залог. Нет долга — «Долга нет · 0 ₾»; переплата — «На счету клиента N ₾».

## 6. Критерии приёмки

QA http://127.0.0.1:5185; записи — созданные в сценарии («ТЕСТ …»); «телефон» — 375 px, «ноутбук» — 1280 px;
RU и KA на телефоне.

### Форма денег

1. **Дано:** владелец, телефон, тестовая аренда с долгом 150. **Действие:** «＋ → Принять деньги» → клиент →
   чип «150 · долг» → наличные → «Записать». **Ожидаем:** 4–5 касаний; перед записью «Закроет: неделя …»
   и новое «оплачено по»; после — долг 0 в аренде, клиенте и поиске.
2. **Дано:** тестовая аренда, ждёт 330 (неделя 150 + залог 180). **Действие:** карта 330. **Ожидаем:** до
   записи «Банк зачислит 325,05; комиссия 4,95»; в платеже брутто 330, комиссия 4,95; долг 0.
3. **Дано:** та же ситуация. **Действие:** наличные 100. **Ожидаем:** «Закроет: залог 100 из 180, неделя 0 из
   150», остаток долга 230.
4. **Дано:** долг 150. **Действие:** 170 наличными. **Ожидаем:** «лишнее 20 — на счёт клиента»; клиент:
   «На счету 20 ₾».
5. **Дано:** менеджер. **Действие:** «＋ → Принять наличные». **Ожидаем:** нет полей канала, даты и
   направления; платёж — наличные сегодня, в его кассе.
6. **Дано:** тестовая продажа с рассрочкой. **Действие:** взнос картой 1 396. **Ожидаем:** комиссия 20,94
   записана; взнос N погашен.
7. **Дано:** залог получен 180, решено вернуть всё. **Действие:** «Залоги → К выдаче → Выдать» наличными.
   **Ожидаем:** в «Платежах» −180, наличные, кто выдал; в кассе выдавшего −180; залог закрыт; больше 180
   ввести нельзя.
8. **Дано:** «Выдать залог» другому человеку. **Ожидаем:** причина обязательна; в журнале — кто и кому.
9. **Дано:** тестовая закупка. **Действие:** оплата 2 541,42 GEL и 6 000 CNY. **Ожидаем:** курс 0,42357 показан;
   платёж — расход, перевод.
10. **Дано:** только что записан платёж. **Действие:** «Отменить» в сообщении за 10 с. **Ожидаем:** платёж
    аннулирован, в журнале «отменено сразу», долг вернулся.

### Разобрать и выписки

11. **Дано:** владелец, внесён вручную перевод 150 от 17.09 по тестовой аренде. **Действие:** загрузить
    синтетическую выписку со строкой 150 от 18.09 с именем тестового клиента. **Ожидаем:** предпросмотр
    «совпало с внесёнными 1»; платёж по аренде один, у него есть строка выписки.
12. **Дано:** та же строка от 25.09. **Ожидаем:** не связь с внесённым: подсказка или правило по §3.2.
13. **Дано:** два внесённых платежа-кандидата. **Ожидаем:** строка в группе «Похоже, уже записан» с обоими;
    новый платёж не создан.
14. **Дано:** спорная тестовая аренда с долгом 320, строка карты «Tanxa:GEL 320; sakomisio: GEL 4.80» без
    имени не в день выдачи. **Ожидаем:** строка в очереди; платёж не создан.
15. **Дано:** новая тестовая аренда, выданная сегодня, строка карты 320 сегодня. **Ожидаем:** привязана
    правилом, брутто 320, комиссия 4,80; видна в «Разобрано правилами» с причиной.
16. **Дано:** тестовый клиент с возвращённой арендой и долгом 150, строка 150 с его именем. **Ожидаем:**
    первая подсказка — его аренда, «Имя совпало», главной кнопкой.
17. **Дано:** строка 1 396 от тестового покупателя. **Действие:** «Другое» → SL-… . **Ожидаем:** взнос
    погашен; не больше 3 касаний после открытия строки.
18. **Дано:** телефон, строка с подсказкой. **Действие:** двойной тап «Привязать». **Ожидаем:** один
    платёж; «Привязано … · Отменить».
19. **Дано:** API-тест, два параллельных запроса привязки одной строки. **Ожидаем:** один успех, второй —
    отказ «строка уже привязана» с переводом.
20. **Дано:** платёж из выписки. **Действие:** «⋯ → Аннулировать», причина. **Ожидаем:** строка снова в
    «Разобрать», привязывается к другой записи; в журнале — что гасил платёж.
21. **Дано:** «Разобрано правилами». **Действие:** «Отвязать». **Ожидаем:** строка в очереди, платёж

### Платежи, касса, залоги, долг

## 8. Что убрать, когда волна принята

- `PaymentsPage`, `StatementsPage` и их адреса (остаются переадресации на `/money/…`).
- `PaymentForm` и панели платежа в карточках аренды, продажи, закупки; поле «выкуп наличными» без канала.
- Три копии формулы долга и баланса клиента — остаётся одна функция в `shared`.
- «Отменить» в строке таблицы платежей (переезжает в меню страницы платежа).
- Временная «Касса» менеджера как фильтр платежей (волна 1) — её место занимает настоящая касса.
- Неиспользуемые строки словарей `payments`, `statements`, `balance` после замены.

Новые грузинские строки волны — одним файлом на вычитку (register #15). Предложения дизайнера:
დასახარისხებელი (Разобрать), ჰგავს, უკვე გატარებულია (Похоже, уже записан), დეპოზიტები (Залоги),
«მიბმა … -ზე» (Привязать к …).
