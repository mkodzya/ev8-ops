## 1.2 Сквозные процессы: от события до денег

Обозначения: 👤 кто · 📱 телефон · 💻 ноутбук · ⏳ ждёт внешнего · ✖ нет в продукте.

### П1. Аренда: лид → выдача → недели → возврат → залог

```
Kommo: лид, чат, тест-драйв (⏳ связи нет)
  → Клиент: поиск по телефону / новый + фото удостоверения и прав        👤 менеджер 📱
  → Выдача: мопед парка аренды → условия (тариф модели, залог 180,
    адрес ночёвки, батареи и зарядки) → акт (пробег, фото)                 👤 менеджер 📱
  → Первый платёж: неделя + залог = 330 (карта: банк зачислит 325,05)     👤 менеджер 📱
  → Договор и акт PDF ka/en → клиенту                                    📱
  → Каждые 7 дней: новая неделя; «оплачено по»                           ночной прогон
  → За день до конца недели: напоминание (⏳ WhatsApp)
  → Оплата: наличные в шоуруме · карта через POS · перевод
  → Выписка → разбор → «оплачено по» сдвинулось                          👤 владелец 📱💻
  → Просрочка: 1-й, 3-й день — напоминание (⏳), звонок                   👤 владелец, менеджер 📱
  → Возврат: акт (ключ, батареи, зарядки, пробег ≥ выдачи, фото)          👤 менеджер 📱
  → Расчёт: долг, опоздание 30 ₾/день, ключ 250 ₾ — предложены            система
  → Залог: вернуть / удержать с основанием                               👤 владелец 📱
  → Удержание или возврат не плательщику: решение одного владельца, без второго подтверждения (В1)
  → Выплата залога: наличные / перевод → исходящий платёж                 👤 владелец 📱
  → Мопед: свободен или в сервис + точка                                 👤 менеджер 📱
```

Правила: `rental.md`, `money.md`, договор п.3–7. Досрочный возврат — неделя целиком (Mika, 17.09.2026).
Выкуп из аренды (RNT-07) — ответвление: часть платежа копится к целевой сумме, по достижении мопед
переходит клиенту событием «продан» (сейчас условие хранится, накопленное не считается — R12).

### П2. Продажа и рассрочка

```
Тест-драйв (Kommo) → продажа по VIN из парка продажи, цена из модели, комплектация  👤 владелец 📱
  → предоплата (канал; карта с комиссией 1,5 %) → график N ежемесячных взносов
  → договор / счёт PDF (✖) → гарантия 12 мес.
  → взносы → просрочка по графику в «Сегодня»
  → выкуп обратно: исходящий платёж, мопед в парк «свободен» или «в сервис»,
    остаток графика закрывается (Q20)
```

Правила: `sales.md`, `pricing.md`. Рассрочка Credo неактуальна (Mika, 17.09.2026).

### П3. Закупка → оплата → приёмка → себестоимость

```
Поставщик (новый — ✖ S1) → заказ в CNY по строкам, новая модель из строки      👤 владелец 💻
  → оплаты поставщику в GEL (сумма в валюте, канал, комиссия банка — ✖)
  → логистика и растаможка на партию (позже создания — ✖)
  → приёмка по CMR: VIN по строкам, цвет, год, парк, точка (частично — S4)
  → себестоимость на VIN = оплаченные GEL / сумма инвойса × строка + логистика поровну
  → доплата после приёмки пересчитывает (✖ S2, Q23)
  → мопеды в парке: парк аренды или продажи решает владелец
```

Правила: `purchasing.md`. С раундом — партия 50 S70 и 30 батарей (`finance-plan.md`).

### П4. Сервис и склад

```
Повод: повреждение в акте возврата · звонок клиента · осмотр        👤 владелец 📱 (менеджер сообщает)
  → заявка: мопед, причина, фото, мастерская; мопед → «в сервисе»
    (у арендатора — остаётся у арендатора, заявка помнит аренду)
  → запчасти со склада (остаток может уйти в минус — красным)
  → за чей счёт: компании / клиента → удержание из залога или долг (Q26)
  → закрыть: дата, пробег, куда встал → мопед «свободен» + точка
Склад: нехватка «держать не меньше» → задача → заказ через закупку → приход
Инвентаризация с причиной — владелец
```

Правила: `service.md`. Механика как роли нет (Mika, 17.09.2026). Своей мастерской и механика в штате нет:
ремонтируют Avtos workshop и курьер, который взялся за ремонт; работа — 50 GEL в час × время, нормы
времени задаёт компания (Kardu, 17.09.2026). Обслуживание — за счёт компании, поломки — за счёт клиента.

### П6. Батареи и точки

Сейчас: с мопедом выдают две батареи и две зарядки; возврат проверяет каждую. Замена разряженной батареи —
только в шоуруме, входит в аренду, **не учитывается**. Батарей 42: 6–8 в шоуруме на замену, 34–36 у
курьеров; их не хватает, из-за этого мопеды после ремонта могут не выйти в аренду (Kardu, 17.09.2026;

«Закупки» → «Новый заказ» → поставщик (найти или создать в том же поле) → строки CNY (модель из

### С8. Неделя владельцев — 💻

«Отчёты» → «Неделя» (понедельник по Asia/Tbilisi) → цифры `weekly.md` + загрузка парка → каждая цифра
ведёт в список, из которого сложена → «Печать / PDF» для встречи. Решения и задачи недели пишутся в книгу
(`weekly/`), не в систему.

### С9. Перенос действующего бизнеса — владелец 💻, один раз

«Настройки» → «Перенос»: аренда «с середины» (оплачено по, залог получен ранее) · продажа с оплаченными
взносами · остаток склада с себестоимостью · долг поставщику. Каждый — форма с пометкой «перенос» в
журнале и в «Экономике» отдельной строкой (Q3). Закрывает B3-02…B3-05.

## 3.1 Принципы

Шестнадцать правил. У каждого — как проверить на приёмке.

| № | Принцип | Что значит | Проверка |
|---|---|---|---|
| 1 | **Экран — это работа, а не таблица базы** | Раздел отвечает на вопрос человека («всё ли с деньгами»), а не показывает сущность. Два экрана про один вопрос — дефект | Раздел назван делом или предметом дела; очередь одного вопроса живёт в одном месте |
| 2 | **«Сегодня» — очередь, в строке — действие** | Строка говорит кто, почему и сколько; главное действие нажимается в самой строке, без захода в карточку | От строки до записанного результата ≤ 3 действия |
| 3 | **Одно главное действие у большого пальца** | Телефон: «＋» в нижней панели, в карточке и мастере — кнопка в липкой полосе снизу. Ноутбук: справа в шапке. Второстепенное — в меню «⋯» | На каждом экране ровно одна залитая кнопка |
| 4 | **После создания — в запись, «Готово» предлагает следующее** | Создал продажу — открыта продажа; выдал — договор, оплата, отправка клиенту | Ни одно создание не возвращает в список |
| 5 | **Одна форма денег, одна цифра долга** | Приход и расход по любому основанию — одна форма; сумма подставлена («к оплате 330 = 150 + 180»); нетто карты видно до подтверждения; долг клиента везде одинаковый | Сумма долга в «Сегодня», аренде и клиенте совпадает |
| 6 | **Ничего не теряется и не задваивается** | Черновик на устройстве; одно нажатие — одна операция; кнопка показывает «отправляется / записано / не записалось — повторить»; нет связи — это видно | Перезагрузка мастера не теряет введённое; двойной тап даёт одну запись |
| 7 | **Чего не могу решить я — становится задачей того, кто может** | Менеджер не решает залог — возврат не блокируется, строка уходит в «Сегодня» владельцев | Ни одного тупика вида «решить нельзя» |
| 8 | **Поиск с первого символа, везде** | Одна строка поиска в шапке: 4 знака VIN, имя в любом написании, телефон с любыми пробелами, номер записи; результаты по группам | Клиент по 4 цифрам телефона — за 2 действия с любого экрана |
| 9 | **Состояние — цвет, форма и слово** | Пилюля с фигурой и словом, одинаково в списке, карточке и PDF; цвет никогда не единственный носитель | Чёрно-белый скриншот читается |
| 10 | **Цифра ведёт туда, из чего сложена** | Любая сумма или счётчик — ссылка на отфильтрованный список; формула — одна функция для экрана и отчёта | Сумма списка = цифре, из которой пришёл |
| 11 | **Пустое — следующее действие, ошибка — что делать** | «Просрочек нет» + полезное действие; «Мопед в сервисе — выдать нельзя. Открыть ремонт?» на языке человека; код ошибки — мелко | Нет экрана без пустого состояния; нет английского кода в тексте |
| 12 | **Три языка равны** | Каждый выбирает ka / ru / en сам; грузинский — самый длинный, макет держит его без обрезки: подписи переносятся, а не режутся; числа, даты и деньги — по языку интерфейса | Каждый экран проверен на KA на 375 px |
| 13 | **Улица и одна рука** | Цель касания ≥ 44 px (главная — 52), расстояние между целями ≥ 8 px; текст ≥ 4,5:1, границы полей ≥ 3:1; «в порядке» — выбор по умолчанию там, где он чаще всего верен | Контраст измерен, а не на глаз |
| 14 | **Задним числом — с причиной и следом** | Правка денег, дат, состояния — причина обязательна, запись в журнал «было / стало»; опасное — подтверждение словами действия («Удержать 180 ₾?»); обратимое — отмена 10 с вместо подтверждения | Каждое изменение видно в журнале |
| 15 | **Автоматика предлагает, человек решает** | Правила и ИИ предлагают с объяснением «почему»; деньги, залог и состояние мопеда подтверждает человек | У каждой подсказки есть строка причины |
| 16 | **Всё, что печатается, — в бренде** | Договор, акты, счёт — те же шрифты и цвета, ka главный, en второй | PDF с первого раза из карточки |

### Правила экранов

- **Списки.** Телефон (< 720 px) — карточки: первая строка — кто или что, справа сумма или состояние;
  вторая — тихая. Над списком: поиск, сегменты со счётчиками, сортировка выбором. Ноутбук (≥ 900 px) —
  таблица, любой заголовок сортирует (U17), строка кликается целиком. Фильтр, сегмент, сортировка и поиск
  живут в адресе. Длинный список — «Показать ещё», без бесконечной прокрутки.
- **Карточка записи.** Шапка: название, пилюля состояния, одна ключевая цифра («оплачено по 19.09»,
  «долг 330 ₾»). Ниже — блоки по делу, в конце — лента событий. Главное действие зависит от состояния
  (просрочена → «Принять оплату», возврат сегодня → «Принять возврат») и стоит в липкой полосе на
  телефоне.
- **Формы.** До 6 полей — лист снизу на телефоне, панель справа на ноутбуке (U18). Больше или несколько
  шагов — мастер: шаг = экран, «Далее» в липкой полосе, «Назад» не теряет введённое, итог перед
  подтверждением. Поле с выбором из больше 7 вариантов — выбор с поиском, не выпадающий список.
- **Шапки страниц и блоков** — как U19 и U20: название и тихая строка «сколько» на одной линии.
- **Движение** — как U16: приходит с той стороны, которой принадлежит; `prefers-reduced-motion` — ничего
  не движется.

## 3.2 Состояния: одинаковые во всей системе

Шесть состояний, которые должен иметь каждый экран и каждый компонент, получающий данные или отправляющий
действие.

| Состояние | Как выглядит | Текст (ru; ka и en — в словарях) | Действие |
|---|---|---|---|
| **Пусто** | Иконка-контур, одна строка, одна кнопка; в очереди «Сегодня» — зелёная галочка | «Просрочек нет» · «Ремонтов пока нет» · «На сегодня всё» | Полезное следующее: «Выдать мопед», «Загрузить выписку» |
| **Загрузка** | Скелет той же формы, что содержимое (строки, карточки), фон `surface-2`, без мерцания при reduced motion; до 300 мс ничего не показывается | — | — |
| **Ошибка загрузки** | На месте содержимого: «Не загрузилось», причина одной строкой, код мелко | «Не загрузилось. Сервер не ответил» | «Повторить» |
| **Нет связи** | Полоса под шапкой, `surface-2` + значок облака: чтение — «Нет связи — показаны данные на HH:MM»; отправка — «Нет связи — сохранено на телефоне, отправим, когда появится» | см. слева | Кнопка отправки остаётся доступной (см. ниже) |
| **Нет прав** | Раздела нет в меню. Прямая ссылка — «Это видят владельцы» и «На „Сегодня“». Действие без права не показывается; вместо него — тихая строка «Решит владелец» | «Это видят владельцы» | «На „Сегодня“» |
| **Успех** | Короткое сообщение снизу (тёмное, как боковая панель), 5 с; для обратимого — «Отменить» с линией 10 с (`--undo-window`); для созданного — «Открыть» | «Оплата записана · 150 ₾» | «Отменить» / «Открыть» |

**Кнопка отправки** — у каждого действия, которое пишет данные, четыре вида: покой → «Записываем…»
(кнопка неактивна, второе нажатие ничего не делает) → «Записано» (галочка, затем успех) → «Не записалось
— повторить» (причина под кнопкой). У каждой операции ключ: повтор после сбоя не создаёт вторую запись
(B2-01).

**Нет связи при отправке — цель и минимум.** Цель: операция с ключом уходит в очередь на устройстве,
строка в «Сегодня» «Ждут отправки: 1», после связи — отправляется; если сервер отказал (мопед уже выдан
другим), строка «Не записалось» с причиной и действием. Минимум, если разработчик скажет, что очередь
дорога для волны 1: черновик сохранён, кнопка «Повторить», когда связь появилась. Выбор — в плане сборки.

**Что увидел при сборке и уже учёл:** подписи цифр на KA длиннее плитки — плитки растут по тексту, а не
режут слово; кнопка «გადახდის აღრიცხვა» помещается в строку с двумя значками на 375 px; «Ждёт оплаты»
различима без нового цвета.
