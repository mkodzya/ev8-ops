### Решения, которые из кода не видны

Это главное, ради чего этот файл существует. Код показывает, *что* сделано,
а не *почему именно так*.

- **Ничего производного не хранится.** «Оплачено по», статус периода, просрочка,
  себестоимость партии, остаток на складе, экономика мопеда — всё складывается
  из строк, которые это породили. Поэтому сторнированный платёж, исправленный
  ремонт или удалённая строка меняют ответ сразу, и второй копии, которая может
  разойтись с первой, не существует.
- **Курс валюты нигде не хранится** (закупки). Курс — не факт, факт — платежи.
  Строки заказа лежат в валюте продавца, ушедшие с банка GEL делятся по строкам
  пропорционально сумме в инвойсе, остаток — методом наибольшего остатка.
  Проверка: контракт Flybrother ZJQXGLJY0012024, 39 мопедов, 68 394,19 GEL двумя
  платежами, 238,34 GEL логистики на единицу — XL1200 выходит ровно
  **1 689,29 GEL** при фактическом курсе 0,42357 GEL/CNY, то есть метод
  воспроизводит цифру, посчитанную руками. Построчное умножение на округлённый
  курс этого не даёт.
- **Залог — не выручка.** В экономику мопеда и в собранную аренду он не входит;
  то, что удержано при возврате, приходит как ремонт за счёт клиента.
- **Мопед без себестоимости не получает итога вовсе**, а сводка по парку
  отдельно говорит, сколько таких. Незаполненная себестоимость — это не ноль.
- **Расход со склада не запрещён при нехватке.** Ремонт, который случился, — это
  факт; склад — запись о нём, и запись, которая мешает записать факт, учит людей
  не записывать. Остаток уходит в минус, красным, и ровно ради этого есть
  инвентаризация (право `stock.count`, owner и director).
- **Стоимость склада — скользящее среднее.** Коробка колодок из двух поставок по
  разным ценам — одна коробка, никто не помечает, какая колодка из какого
  инвойса. Расход берёт долю стоимости пропорционально, поэтому последняя штука
  уносит ровно остаток и склад обнуляется без копеечного хвоста.
- **Комиссия эквайринга — расход компании**, а не долг клиента: заплативший
  320 картой не должен 4,80. Долги гасятся по брутто.
- **Ночной прогон недель живёт в API** (`apps/api/src/lib/periods.ts`), воркер —
  только часы с общим `WORKER_TOKEN`. Денежные правила существуют в одном экземпляре.
- **Права по умолчанию закрыты:** маршрут без объявленного scope доступен только
  владельцу, и таблица маршрутов подметается тестом.
- **Файлы лежат в Postgres** байтами (как в Self Platform: один pg_dump покрывает всё).
- **Тема только светлая** — тёмную убрали по решению Мики.
- **Склад запчастей — расширение сверх ТЗ.** В §2 он вынесен за границы v1;
  сделан по прямой просьбе Мики, отмечено в `CLAUDE.md`.

## 4. Решения, принятые до старта

- Стек = стек Self Platform, отдельный репозиторий, пакеты `@ev8/*`.
- Деньги в тетри целыми числами, НДС 18 % сверху, TZ Asia/Tbilisi.
- Состояние мопеда выводится из событий; ручной перевод только с причиной.
- Периоды аренды по 7 календарных дней от выдачи; «оплачено по» = конец
  последнего полностью оплаченного периода.
- Банк: BOG через Business Online API только чтение (этап 2), TBC и Credo файлами.
- WhatsApp Cloud API и Lead Ads в v1; Marketing/Conversions API, TBC Integration
  Service, Instagram DM — не в v1.
- Дизайн: бренд ev8.ge как есть, тёмный зелёный #557553 для текста (контраст),

Не писать в Odoo. Не класть реальные данные (снимки, выписки, договоры) в

`ALLOW_DEV_SECRET=true`, и так и должно остаться.
