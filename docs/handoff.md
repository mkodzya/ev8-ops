## 1. НА ЧЁМ ОСТАНОВИЛИСЬ — читать первым

ТЗ v1.1 согласовано как черновик для старта, решение владельца: **полный
переход с Odoo**, Kommo остаётся фронт‑офисом и связывается в обе стороны.
Название продукта решено 14.09.2026: **EV8 Ops**.

Сделано 14.09.2026 (Этап 1, шаги 1–2 и основа шага 4): монорепо `apps/api`
(Fastify 5 + Prisma 7), `apps/worker` (ночной прогон недельных периодов),
`apps/web` (React 18 + Vite 6, PWA, ka/ru/en, i18n‑guard), `packages/shared`
(деньги в тетри, НДС, эквайринг, периоды, роли); compose db/api/worker/web на
портах 5433/8082/5175 (Self Platform занимает 5432/8080/5173 и 5174/8081);
`.command`‑скрипты; миграция `0001_init.sql` (users, sessions, vehicle_models,
vehicles, vehicle_events, customers, rentals, rental_periods, deposits, acts,
audit_log; роли owner/director/manager/mechanic/accountant); CI.

Операции (API + экраны): новый клиент с проверкой дублей (CST‑02), выдача
мастером на телефоне в 5 шагов (RNT‑01: аренда + первый период + залог + акт
выдачи + событие → rented, одной транзакцией), выдача без VIN с пометкой
(RNT‑06), возврат в 2–3 шага (RNT‑04: акт возврата, мопед → available;
решение по залогу только у director/owner, удержание и возврат третьему лицу
ждут подтверждения owner — RNT‑05), ручной перевод состояния только с
причиной и не в rented (FLT‑03), карточки мопеда / аренды / клиента с лентой
событий, периодами, актами и залогом; журнал изменений на каждой записи.

По решению Мики 14.09.2026 данные из Odoo пока **не** заливаем: сначала
собираем продукт. Для проверки экранов есть демо‑набор, каждая запись
помечена DEMO (`SEED_MODE=demo`, «Reset EV8 Ops (DEMO data).command»); сид
отказывается его ставить без ALLOW_DEV_SECRET=true, то есть на стендах.
Node на Mac не установлен — всё гоняется в `node:22-alpine` (см. README).
Проверено: 23 unit‑теста shared, 19 тестов api на `ev8ops_test`, i18n‑guard,
typecheck; в браузере выдача и возврат с телефона (375 px), карточки, ручной
перевод в сервис, три языка, обе темы.

Не сделано в шаге 4 и почему: фото в актах (нужно файловое хранилище — с
ним же придут документы клиента, CST‑03); договор и акты PDF (RNT‑08) — нужен
шаблон компании из Drive, без него текст пришлось бы выдумать; оплата
периодов и «оплачено по» из платежей — этап 2 (PAY‑*), пока поле
`paid_through` заполняет только импорт/демо; правило последней недели при
досрочном возврате — открытый вопрос, пока полная неделя, а неоплаченные
периоды после даты возврата удаляются.

Следующие шаги на выбор: (а) файловое хранилище + фото в актах + документы
клиента; (б) PDF договора и актов по шаблону из Drive; (в) `tools/migrate_stage1.py`
(Odoo read‑only → модели, мопеды, клиенты, аренды, периоды, залоги, сверка
контрольных цифр из п. 3) — когда Мика скажет заливать данные.

Открытые вопросы к Мике (раздел 12 ТЗ), спрашивать по ходу, а не пачкой:
тариф Kommo с вебхуками; перенос номера WhatsApp из Kommo

эквайера BOG; НДС‑фактуры rs.ge (Polaris или мы); язык по умолчанию; хостинг;

## 4. Решения, принятые до старта

- Стек = стек Self Platform, отдельный репозиторий, пакеты `@ev8/*`.
- Деньги в тетри целыми числами, НДС 18 % сверху, TZ Asia/Tbilisi.
- Состояние мопеда выводится из событий; ручной перевод только с причиной.
- Периоды аренды по 7 календарных дней от выдачи; «оплачено по» = конец
  последнего полностью оплаченного периода.
- Банк: BOG через Business Online API только чтение (этап 2), TBC и Credo файлами.
- WhatsApp Cloud API и Lead Ads в v1; Marketing/Conversions API, TBC Integration
  Service, Instagram DM — не в v1.
- Дизайн: бренд ev8.ge как есть, тёмный зелёный #557553 для текста (контраст),
  Noto Sans Georgian для грузинского, пилюльные кнопки, боковая панель вместо
  модалок на ноутбуке, мастер по шагам на телефоне.

## 6. Чего не делать

Не писать в Odoo. Не класть реальные данные (снимки, выписки, договоры) в
репозиторий. Не выдумывать VIN, даты, суммы и имена для «правдоподобия».
Не трогать Drive на удаление. Не публиковать страницы с данными клиентов
как артефакты — классификатор их блокирует, отдавать файлом.
