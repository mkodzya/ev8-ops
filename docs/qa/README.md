# QA-стенд и отчёты тестирования

## Два стенда на одном Mac

| | Рабочий стенд | QA-стенд |
|---|---|---|
| Адрес | http://localhost:5175 | **http://127.0.0.1:5185** |
| API / база | 8082 / 127.0.0.1:5433 | 8092 / 127.0.0.1:5443 |
| Compose-проект | `ev8-ops-platform` | `ev8-ops-qa` |
| Данные | живые, перенесены из Odoo | копия рабочего стенда |
| Кто пишет данные | никто из агентов | дизайнер и тестировщик, разработчик при проверке |
| Доступ | со всех интерфейсов | только с этого Mac (127.0.0.1) |

QA-стенд открывается **по 127.0.0.1, не по localhost**. Браузер хранит куки по имени хоста, а не по
порту: на двух «localhost» у стендов была бы одна кука сессии, и вход в один выкидывал бы из другого.
Логины и пароли на QA те же, что на рабочем стенде (это копия базы); входит Mika, агенты пароли не
вводят.

## Управление — `scripts/qa-stand.sh`

```bash
scripts/qa-stand.sh up        # первый запуск: образы + копия базы + старт
scripts/qa-stand.sh images    # новый код после слияния, данные QA сохраняются
scripts/qa-stand.sh refresh   # новый код и свежая копия базы (всё, что создал тестировщик, пропадёт)
scripts/qa-stand.sh down      # остановить (том базы остаётся)
scripts/qa-stand.sh status
```

Скрипт ничего не собирает. Собирает рабочий стенд, QA берёт те же образы под своим именем: одна
тяжёлая сборка вместо двух.

Порядок после слияния блока в `develop`:

1. `nice -n 10 docker compose up -d --build web api worker` — пересобрать рабочий стенд;
2. `scripts/qa-stand.sh images` — QA на новом коде (миграции применяются при старте API);
3. `scripts/qa-stand.sh refresh` — только если тестировщику нужны чистые данные.

Память: рабочий стенд ~300 МБ, QA ~340 МБ. Если рядом идёт сборка или Playwright, QA на это время
останавливать (`down`).

Копия базы содержит личные данные клиентов. Она живёт только в томе Docker на этом Mac; дампы в
репозиторий, в `docs/` и в отчёты не кладутся.

**Записи тестировщика живут до первого `refresh`.** После волны 5 на QA остались данные, на которых
волна ломалась и была починена: партия, принятая без оплаты (`PO-00117`, `PO-00118`), объединённый
клиент, отменённый ремонт с возвратом запчастей, перенесённая продажа. Их не воспроизвести на чистой
базе, а `scripts/qa-stand.sh refresh` стирает их одной командой — и сделать это может кто угодно.
Если такой снимок нужен дальше текущей волны, его снимают `pg_dump` **вне репозитория** (в нём живые
клиенты и телефоны — место для него `~/Desktop/EV8-ops/`, не git). Решение — за Mika; по умолчанию
снимок не снимается, и история живёт до первого `refresh`.

## Ловушки экранной проверки

Каждая уже давала ложную находку — проверять до того, как писать в отчёт.

- **Как проверяют.** Вкладка Chrome на `http://127.0.0.1:5185/api/health`, в неё скриптом вставляется
  `<iframe>` 375×720 на приложение (ноутбук — 1280×800); язык — `localStorage['ev8-lang']` = `ru` |
  `ka` | `en`. Экран читается через DOM того же origin, действия — `.click()` по найденным узлам: DOM
  работает и при свёрнутом окне, скриншоты — нет. После выкатки — перезагрузка с cache-buster.
- **`innerText` склеивает соседние inline-узлы** без пробела («ТЕСТ QA ТетаQatest Theta»). Прежде чем
  писать «слиплось» — `getBoundingClientRect()` и `margin`.
- **Поиск кнопки по подписи берёт первую в документе.** У менеджера «Принять наличные» есть и на
  строках «Просрочены», и в листе «＋». Целиться внутрь нужного узла.
- **Списки рисуются дважды** — карточками (`li`, телефон) и таблицей (`tr`, скрыта). Клик и замер — по
  видимому; «за краем» не считать то, что лежит в предке с `overflow: hidden | auto | scroll`.
- **PDF во встроенном просмотрщике Chrome** снимок не отдаёт и синтетическую прокрутку не принимает;
  страницы — якорем `#page=N` с cache-buster. Вёрстку PDF глазами смотрит человек.
- **Часовой пояс.** Продукт живёт по Asia/Tbilisi. Машина в Europe/London с 20:00 UTC до полуночи видит
  «вчера» в любой дате, посчитанной по UTC или по часам устройства (в волне 6 — две находки подряд).
  Дату сверять с базой: `select now(), (now() at time zone 'Asia/Tbilisi')`.
