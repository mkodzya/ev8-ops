## Баги

### QA-W1-01 · Блокер · Критерии 19, 20, 16, §3.8 · Без связи любой список висит вечным скелетом

- **Экран, роль, устройство:** любой список (проверено: Продажи, Закупки, Деньги → Платежи, поиск),
  владелец, телефон и ноутбук, RU.
- **Шаги:** 1) открыть приложение; 2) `docker stop ev8-ops-qa-api-1`; 3) перейти в «Продажи» по нижней
  панели (без перезагрузки); 4) ждать.
- **Ожидалось:** «Не загрузилось», причина, код мелко, «Повторить» (критерий 19); полоса «Нет связи —
  данные на HH:MM» (критерий 20); «вечной «Загрузки» нет» (§3.8).
- **Получилось:** скелет из четырёх строк и больше ничего — 40 секунд и дольше. В сети ровно **один**
  запрос (`GET /api/payments` → 500 от шлюза за 38 мс), повторной попытки нет, ошибка на экран не
  попадает. Полосы «Нет связи» нет ни на одном экране, в том числе на уже загруженных «Клиентах».
- **После возвращения связи** застрявший экран не оживает: скелет остаётся, пока не уйти в другой раздел
  и не вернуться. У Kardu на плохой связи экран «залипает» до перезахода.
- **Где смотреть:** `lib/use.ts` `useLoad` отдаёт `failure` только при `q.error`; запрос остаётся
  `pending`, повтор из `lib/queryClient.ts` (`retry: … count < 1`) не выполняется. Страницы (`SalesPage`,
  `PurchasesPage`, `PaymentsPage`) `LoadError` рисуют правильно — до него не доходит.
- **Регрессия:** в блоке 1 этот сценарий работал — «Не загрузилось» и «Повторить» за секунду.

### QA-W1-02 · Обычный · Критерий 16 · Поиск без связи не ищет среди недавних

- **Экран, роль:** поиск в шапке, владелец, телефон.
- **Шаги:** открыть мопед ···8588 (он попадает в недавние), остановить API, поиск «7372».
- **Ожидалось:** «Нет связи — ищем среди недавно открытых», найденное из недавних; не вечное ожидание.
- **Получилось:** скелет групп навсегда (ждал 25 секунд). Запрос, совпавший с прошлым («8588»),
  показывается из кэша без пометки, что данные старые.

### QA-W1-03 · Обычный · Критерий 4, §3.2 · На экране «Чей возврат?» нет группы «Возврат сегодня»

- **Экран, роль:** «＋» → «Принять возврат», владелец, телефон, KA и RU.
- **Ожидалось (§3.2):** сверху группа «Возврат сегодня» — плановая дата сегодня или прошла; ниже — все
  действующие.

### QA-W1-04 · Обычный · Критерий 32 · Цели касания меньше 44 px

- **Экран:** все разделы, телефон (замерено по `getBoundingClientRect`).

- **Получилось:** 34 px — вкладки раздела («Ремонты», «Склад», «Мопеды», «Модели», «Точки», «Платежи»,
  «Выписки»), все чипы фильтров, кнопки действий страницы («+ Новая запчасть», «+ Добавить мопед»,
  «Новый клиент», «Новая выдача»), кнопки строк на «Сегодня» («Отметить оплату», «Напомнить»); 42 px —
  поля поиска в списках; 36–38 px — чипы парка и ссылки моделей. 44 px и больше — только шапка, поля
  форм и нижняя панель. Граница поля `#7a7a7a`, «＋» 52 px, оранжевой кнопки нет — это в порядке.

## Расхождения с прототипом

1. **Отказ по полю красит кнопку в «Не записалось — повторить».** В прототипе (`wave-1-forms-states.html`,
   «Отказ по полю») кнопка остаётся «Добавить запчасть». Человек читает «не записалось» там, где надо
   просто исправить артикул.
2. **Поиск без подсветки совпадения** (QA-W1-05).
3. **Меню аватара владельца:** в §3.2 пункт «Сервис · Склад», собрано — «Сервис».
4. **«Деньги → Платежи»:** два ряда чипов — «Очередь 0 · Все 159» и ниже «Все 159 · Сегодня 0 · За
   неделю 0 · Перевод…»; «Все 159» дважды на одном экране.
5. **Подсказка на карточке аренды у менеджера:** «Менеджер проводит наличные. Перевод и карту заводит
   директор.» — роли «директор» после волны нет; должно быть «владелец».
6. Отклонения 1–13 из `wave-1-ready.md` проверил: причины честные, кроме отклонения 3 (таблица «Мопеды
   по моделям» на телефоне) — из-за неё QA-W1-06.
