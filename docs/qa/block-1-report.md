## Баги

### QA-1-01 · Критичный · B1-01 · Выход без связи оставляет сессию открытой

- **Экран, роль:** «Мой вход» → «Выйти» (и «Ещё» → «Выйти» — тот же код `session.tsx` `logout`), владелец. Компьютер.
- **Шаги:** 1) войти; 2) остановить API (`docker stop ev8-ops-qa-api-1`) — это то же, что пропавший интернет на
  телефоне; 3) «Мой вход» → «Выйти»; 4) открылся экран входа; 5) API запустить; 6) открыть адрес приложения.
- **Ожидалось:** человек вышел — следующий, кто возьмёт общий телефон, видит вход (ТЗ B1-01: «Команда не может
  работать с общего телефона», книга `project.md` «Люди и роли» — менеджеры на точке с телефона; ТЗ v1.1 §8).
- **Получилось:** экран входа показан, но сессия на сервере жива (`/api/me` → 200). Шаг 6 открывает «Сегодня»
  под владельцем без пароля. Никакого сообщения, что выйти не удалось.
- **Где:** `logout` делает `setMe(null)` в `finally` при любой ошибке `POST /api/auth/logout`; кука остаётся.
- **Скриншот:** не сохранён в файл (инструмент браузера не отдаёт файл); воспроизводится за минуту по шагам.

### QA-1-02 · Обычный · B1-02 · Вечная «Загрузка…» на четырёх экранах и в мастере выдачи

- **Экран, роль:** «Модели», «Настройки» (оба блока), «Выписки» (оба блока), мастер выдачи шаг «Клиент»; владелец;
  компьютер и 375 px.
- **Шаги:** открыть приложение → остановить API → перейти по меню на экран (без перезагрузки страницы), подождать 6 с.
- **Ожидалось:** «Не загрузилось» и «Повторить», не вечная загрузка (ТЗ B1-02, приёмка 4; `docs/design/ux.md` №9).
- **Получилось:**
  - «Модели» — «Загрузка…» навсегда.
  - «Настройки» — «Загрузка…» в «Люди и входы» и в «Точки».
  - «Выписки» — «Загрузка…» в «Очередь» и «Выписки», а в заголовке **«0 выписок»** — неправда при недоступном API.
  - «Склад» — только строка «Нет связи с сервером…», без «Не загрузилось» и без «Повторить».
  - Мастер выдачи, шаг «Клиент»: поиск «Akaki» ничего не показывает и ни о чём не предупреждает. Единственный путь
    дальше — «Новый клиент», то есть дубль клиента, который уже есть.
- **Где:** эти страницы не используют `LoadError` (`ModelsPage`, `SettingsPage`, `StatementsPage`, `StockPage`,
  `PickupWizard`, `CustomerForm`).

### QA-1-04 · Обычный · B1-05 · Механик видит на «Сегодня» аренды, долги клиентов, залоги и продажи

- **Экран, роль:** «Сегодня», механик. **По коду**, вживую не проверено — на QA нет учётки механика.
- **Ожидалось:** «Недоступный раздел нигде не показывается» (ТЗ B1-05); в `block-1-ready.md`: «Аренд», «Продаж»,
  «Платежей», «Выписок» у механика нет нигде.
- **Получилось (код `TodayPage.tsx`, `lib/tasks.ts`, `/api/summary` — scope `session`):** механику показываются задачи
  «Выдачи сегодня», «Просрочки», «Без подтверждённого VIN» со ссылками на `/rentals`; список «Просрочки, глубокие сверху»
  с именами клиентов, днями и долгом, ссылки на карточки аренд; плитки «Активные аренды» → `/rentals`, «Просрочка по
  продажам» → `/sales`, «Залоги на руках». Бейдж «Сегодня» считает и аренды. Маршруты `/rentals`, `/sales` в
  `App.tsx` не закрыты — по ссылке механик попадает в раздел, которого нет в меню.
- Права API — это B9-02; здесь речь только о том, что показывает экран.

### QA-1-05 · Обычный · B1-02 · Выписка больше ~9,6 МБ — «Не получилось… (FST_ERR_CTP_BODY_TOO_LARGE)»

- **Экран, роль:** «Выписки → Загрузить выписку», владелец. Проверено запросом к API с телом 10 МБ.
- **Ожидалось:** «Файл слишком большой: выписка — до 8 МБ.» (код `file_too_big` уже есть в словарях).
- **Получилось:** 413 `{"error":"FST_ERR_CTP_BODY_TOO_LARGE"}` — лимит тела (8 МБ × 1,2) срабатывает раньше проверки
  размера в обработчике; экран покажет неизвестную ошибку с кодом. В браузере размер файла до отправки не проверяется.
- **Шире:** `errors-guard` не видит коды самого Fastify (`FST_ERR_CTP_INVALID_JSON_BODY`, `…BODY_TOO_LARGE`,
  ответ на неизвестный маршрут `"error":"Not Found"`) — `server.ts` отдаёт их как есть.

### QA-1-07 · Мелкий · B1-02 · Отказ продажи говорит «нельзя выдать»

- **Экран:** форма продажи (API `POST /api/sales`), любой язык.
- **Получилось:** продажа мопеда не в статусе «свободен» отвечает тем же кодом `vehicle_not_available`, что и выдача:
  «Этот мопед сейчас нельзя выдать: он не свободен…». Для продажи слово «выдать» неверно. Через форму не
  воспроизводится (в списке только свободные), только при гонке двух человек.
- **Ожидалось:** текст про продажу. Заодно API присылает `state` (`service`), а текст его не называет — пример из ТЗ:
  «Мопед в сервисе — выдать нельзя. Открыть мопед?».

### QA-1-08 · Мелкий · B1-02 · «Поле заполнено неверно» не говорит, какое поле

- API присылает `field` (`weeklyRateTetri`) для `missing_field` и `bad_field`; текст «Не заполнено обязательное поле.
  Заполните его и попробуйте ещё раз.» не называет поле. ТЗ B1-02: текст «говорит, что делать».

### QA-1-09 · Мелкий · B1-02 · Грузинский текст «Не загрузилось»

- `ka.ts`: `loadFailed: 'არ ჩაიტვირდა.'` — похоже на опечатку, ожидаемая форма «არ ჩაიტვირთა.» Я не носитель: нужна
  вычитка (разработчик в `block-1-ready.md` тоже просит вычитку Kardu).
