## Как читать

- **Блок** — 1–3 дня разработчика, сдаётся и тестируется отдельно (`docs/qa/block-N-ready.md` →
  `block-N-report.md`).
- **Пункт** — `Bn-mm · P · процесс → экран`.
  - **P0** — нужно для переноса;
  - **P1** — важно в первый месяц;
  - **P2** — потом.
- **Правило** — ссылка на книгу, ТЗ v1.1 или ADR, либо **«нужно решение Mika (Qn)»** — вопросы в
  конце. Если у пункта есть «умолчание», его можно делать до ответа. Если умолчания нет — пункт
  ждёт.
- **Приёмка** — сценарии «дано / действие / ожидаем» на QA-стенде http://127.0.0.1:5185.
  - Каждый сценарий начинается с записей, созданных в самом сценарии (клиент «ТЕСТ …»), а не с
    данных стенда.
  - Роль указана. Если не сказано иначе, сценарий проходится на **375 px** и на ноутбуке.
  - Новый текст проверяется в **ka / ru / en**.
- **Общие требования к каждому пункту:**
  - новые строки на трёх языках;
  - деньги в тетри;
  - даты по Asia/Tbilisi;
  - изменение пишется в журнал с «было / стало»;
  - тест на правило в `apps/api/test` или `packages/shared/test`.

### B1-02 · P0 · Все процессы → ошибки и отказы

**Сейчас.**
- Ошибки выводятся как «`код: английский текст`», переведены 2 кода.
- Неверный адрес записи (`/sales/new`) даёт 500 «Something broke on our side».
- Истёкшая сессия показывает `unauthenticated: Request failed (401)`.
- Сетевая ошибка оставляет вечную «Загрузку».

Аудит X2, §4.4.

**Должно быть.**
- **Коды ошибок.** Каждый код API имеет текст на ka / ru / en, который говорит, что делать:
  «Мопед в сервисе — выдать нельзя. Открыть мопед?» Guard, как i18n-guard: код без перевода валит
  проверку.
- **Неизвестная ошибка** — «Не получилось. Повторите или сообщите владельцу» на языке интерфейса,
  код мелко.
- **401** на любом запросе → экран входа, после входа — та же страница.
- **Нет записи или неверный id** → 404 «Запись не найдена» и ссылка на список.
- **Ошибка загрузки списка** → «Не загрузилось» и «Повторить».

**Правило.** `docs/design/ux.md` №9; `CLAUDE.md` «Languages».

**Приёмка.**
1. Дано: владелец, RU, адрес `/sales/new`. Ожидаем: «Продажа не найдена», «К продажам»; в логе API
   нет 500.
2. Дано: KA, создан тестовый мопед и открыт ремонт на него. Действие: выдать этот мопед (API-тест
   или мастер). Ожидаем: грузинский текст с действием, без `vehicle_not_available`.
3. Дано: сессия удалена на сервере. Действие: «Провести платёж» в карточке аренды. Ожидаем: вход,
   затем та же карточка.
4. Дано: API остановлен. Действие: открыть «Аренды». Ожидаем: «Не загрузилось» и «Повторить», не
   вечная загрузка.
5. Дано: в API добавлен код без перевода. Ожидаем: guard красный.

## Блок 2. Деньги без дублей и чужих привязок

### B2-01 · P0 · Выдача, возврат, платежи → повторная отправка

**Сейчас.** Ключа операции нет. После сбоя загрузки фото мастер выдачи остаётся на шаге
подтверждения, и повтор создаёт вторую аренду. То же возможно у возврата и платежа при обрыве
связи. Аудит M1.

**Должно быть.**
- Мастер выдачи, мастер возврата и каждая панель денег (платёж аренды и продажи, выкуп, оплата
  поставщику, решение по залогу) при открытии получают ключ операции и шлют его с подтверждением.
- Сервер по тому же ключу возвращает уже созданную запись.
- Кнопка блокируется на время запроса.
- Если запись создана, а фото не загрузились, мастер переходит на «Готово» с «Фото не загружены —
  повторить».

**Правило.** ТЗ v1.1 §8 («повторная отправка не создаёт дублей»).

**Приёмка.**
1. Дано: менеджер, 375 px, «Slow 3G» в DevTools, тестовый клиент и свободный мопед. Действие:
   «Подтвердить» дважды быстро. Ожидаем: одна аренда.
2. Дано: ответ сервера пришёл, затем сеть выключена во время загрузки фото. Действие: включить
   сеть, «Повторить». Ожидаем: фото у той же аренды, второй аренды нет.
3. Дано: API-тест, два одинаковых запроса с одним ключом — аренда, платёж, возврат. Ожидаем: один
   результат, один и тот же id.

**Зависит от:** —

### B2-02 · P0 · Выписки → очередь: одна строка — один платёж

**Сейчас.** Двойной тап по «Похоже на …» создаёт два платежа. Привязка не в одной транзакции, связь
строки не уникальна. Аудит M2.

**Должно быть.**
- Привязка строки — одна транзакция.
- В базе уникальность «строка — не больше одного действующего платежа».
- Кнопка блокируется на время запроса.

**Правило.** ТЗ v1.1 §8; ADR-0004.

**Приёмка.**
1. Дано: API-тест, два параллельных запроса привязки одной строки. Ожидаем: один успех, второй —
   409 «уже привязана» с переводом.
2. Дано: 375 px, синтетическая выписка из одной строки. Действие: двойной тап по подсказке.
   Ожидаем: один платёж.

**Зависит от:** B2-01

### B2-03 · P0 · Выписки → сверка с уже внесёнными платежами

**Сейчас.** Строка выписки всегда становится новым платежом, даже если такой же перевод или
наличные уже внесены руками. Аудит M3.

**Должно быть.**
- Перед созданием платежа ищется платёж того же клиента или аренды, с той же суммой (брутто или
  нетто), в окне дат и ещё без строки выписки.
- Один кандидат — строка связывается с ним, новый платёж не создаётся.
- Несколько кандидатов — строка идёт в очередь с этими кандидатами.
- Предпросмотр загрузки показывает «совпало с внесёнными — N».

**Правило.** ADR-0004. Окно дат — **нужно решение Mika (Q2)**. Умолчание: ±3 календарных дня,
расхождение суммы — в очередь.

**Приёмка.**
1. Дано: директор, QA, тестовая аренда, внесён перевод 150 от 17.09 вручную. Действие: загрузить
   синтетическую выписку BOG со строкой 150 от 18.09 с именем тестового клиента. Ожидаем:
   предпросмотр «совпало с внесёнными 1»; платежей по аренде по-прежнему 1, у него есть строка
   выписки.
2. Дано: та же строка от 25.09. Ожидаем: новый платёж или очередь по правилам, не связь.
3. Дано: API-тест с двумя кандидатами. Ожидаем: очередь, платёж не создан.

**Зависит от:** B2-02

### B2-04 · P0 · Выписки → правила автопривязки

**Сейчас.** Безымянная карта 320 сама привязалась к спорной аренде трёхмесячной давности: второй
признак не проверялся, спорные аренды не исключены. Аудит M4.

**Должно быть.**
- **Автопривязка** — только при двух признаках:
  - имя плательщика совпадает с клиентом;
  - **или** сумма совпадает **и** дата строки — день выдачи аренды (для типовых сумм эквайринга)
    либо в пределах недели, которую эта сумма закрывает.
- **Одна сумма** без второго признака — только подсказка в очереди.
- **Аренды со статусом «спорная», «пауза», «бронь»** не участвуют в автопривязке.

**Правило.** ADR-0004 («к чужой аренде хуже, чем ни к какой»); книга `money.md` (эквайринг без
имени, разбор по суммам). Автопривязка к спорным — **нужно решение Mika (Q25)**. Умолчание: нет.

**Приёмка.**
1. Дано: API-тест, спорная аренда с долгом 320, строка карты «Tanxa:GEL 320; sakomisio: GEL 4.80»
   без имени, дата не день выдачи. Ожидаем: очередь, платёж не создан.
2. Дано: новая тестовая аренда, выданная сегодня, строка карты 320 сегодня. Ожидаем: привязана,
   брутто 320, комиссия 4,80.
3. Дано: две аренды с долгом 170, строка 170 без имени. Ожидаем: очередь.

**Зависит от:** B2-03

### B2-05 · P1 · Выписки → подсказки и куда можно привязать

**Сейчас.**
- Перевод с именем клиента, у которого аренда закрыта, получает зелёную подсказку «Похоже на»
  чужую аренду.
- Привязать можно только к открытой аренде; подсказки обрезаны до 12.

Аудит M5.

**Должно быть.**
- **Порядок подсказок:** клиент по имени плательщика (любые его аренды и продажи с долгом) → сумма
  и дата → остальное.
- **У подсказки** видны сумма долга и основание: «имя совпало», «сумма и день выдачи».
- **Вторая и следующие подсказки** — не основной кнопкой.
- **Строку можно привязать** к аренде (включая возвращённую с долгом), к продаже (взнос графика), к
  клиенту (переплата) или отметить «Не платёж клиента» с причиной.
- **Выбор** — поиском по номеру, имени, телефону, а не обрезанным списком.

**Правило.** Книга `money.md`, `sales.md` («платёж гасит взносы от старого к новому»).

**Приёмка.**
1. Дано: тестовый клиент с возвращённой арендой и долгом 150, строка 150 с его именем. Ожидаем:
   первая подсказка — его аренда, «имя совпало».
2. Дано: строка 1 396 от тестового покупателя. Действие: «Продажа» → SL-… . Ожидаем: взнос
   погашен.
3. Дано: 375 px. Ожидаем: привязка к продаже — не больше 3 касаний после открытия строки.

**Зависит от:** B2-04, B5-08

### B2-06 · P1 · Выписки → эквайринг по тексту

**Сейчас.** Строка «Wallet/domestic MC cards» без суммы комиссии читается переводом. Правило

признаков — по реальной выписке: **нужен образец BOG от Mika (Q2-b)**. Без образца — только
«Wallet/domestic MC cards».

**Приёмка.**
1. Дано: синтетическая строка «Wallet/domestic MC cards» 325,05 в день выдачи тестовой аренды с
   первым платежом 330. Ожидаем: эквайринг, брутто 330, комиссия 4,95, привязана.
2. Дано: та же строка 300,00. Ожидаем: эквайринг без брутто, в очереди.

## Блок 3. Перенос: начальное состояние

Бизнес переходит в систему, когда в ней правильно заведено то, что уже происходит:
- действующие аренды;
- полученные залоги;
- рассрочки;
- остатки склада;
- долги поставщикам;
- поставщики.

Сейчас это возможно только скриптом из Odoo.

### B3-01 · P0 · Перенос → скрипт не стирает работу команды

**Сейчас.** Повторный запуск `tools/migrate_stage1.py` удаляет всю разноску платежей (`:651`) и

**Должно быть.**
- Скрипт перед записью ищет в базе записи, созданные не переносом: платёж без id Odoo, аренду,
  продажу, закупку без id Odoo, акт, выписку, заявку. Если нашёл — отказ со списком, ничего не
  пишется.
- Разноска пересобирается только для платежей из Odoo.
- `--wipe` на стенде запрещён (признак стенда из B1-04).

**Правило.** `CLAUDE.md` №1: перезапуск разрешён Mika 15.09.2026. Когда перенос закрывается —
**нужно решение Mika (Q1)**. Умолчание: отказ при первой записи команды.

**Приёмка.**
1. Дано: QA, вручную внесён один наличный платёж. Действие: `--apply`. Ожидаем: отказ «1 платёж,
   внесённый в системе»; число распределений и недель до и после одинаково.

**Зависит от:** B1-04

### B3-06 · P1 · Перенос → тип записи и дубли

**Сейчас.**
- Поставщики и сотрудники — среди клиентов и в мастере выдачи.

## Блок 5. Возврат и залог без тупиков

### B5-01 · P0 · Возврат → решение по залогу после возврата

**Сейчас.** Если возврат оформил менеджер, решить залог нельзя никому. Владелец может только
подтвердить, отклонить не может. Аудит M6.

**Должно быть.**
- **Блок «Решить залог».** У возвращённой аренды с нерешённым залогом директор и владелец видят
  блок: получено по залогу, долг по неделям, уже удержано (ремонт).
- **Варианты:** вернуть всё, удержать часть, удержать всё.
- **При удержании** обязательны сумма, основание и причина.
- **При возврате** — кому и каким каналом.
- **Подтверждение владельца.** Удержание и возврат не плательщику ждут его. Владелец подтверждает
  или отклоняет с причиной, отклонённое возвращается директору.
- **«Сегодня»** у директора и владельца: «Залоги без решения — N».

**Правило.** Книга `rental.md` («решает директор; удержание и возврат не плательщику подтверждает
владелец»), `customer-journey.md` §5; ТЗ v1.1 RNT-05. Что с деньгами при отклонении — **нужно
решение Mika (Q13)**. Умолчание: остаются «на руках».

**Приёмка.**
1. Дано: менеджер оформляет возврат тестовой аренды. Ожидаем: «Решение по залогу примет директор».
2. Дано: директор, карточка аренды. Действие: удержать 40, «долг по аренде», причина. Ожидаем:
   «ждёт подтверждения владельца», задача у владельца.
3. Дано: владелец «Отклонить». Ожидаем: задача вернулась директору с причиной.
4. Дано: 375 px. Ожидаем: решение в одной панели снизу.

**Зависит от:** B1-02

### B5-02 · P0 · Возврат → суммы от полученного залога

**Правило.** Книга `money.md` («залог — обязательство перед клиентом»). Выдавать ли мопед с

**Приёмка.**
