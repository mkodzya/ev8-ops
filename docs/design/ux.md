# UX/UI EV8 Ops — принципы и конкретные улучшения относительно демо

Опирается на ТЗ §9, `brand.md`, практики Tuff Stuff Level UP (pill‑кнопки 44 px, четыре
цвета, состояния компонентов), Kultura (пустая выдача открывает экран следующего действия),
и на то, что Odoo делал плохо для команды с телефона.

## Принципы

1. **Экран отвечает на один вопрос.** «Сегодня» — что требует действия. «Парк» — где каждый VIN.
   «Аренды» — кто должен и до когда оплачено. Если экран отвечает на два вопроса, это два экрана.
2. **Первое действие — большая кнопка внизу.** На телефоне у каждого экрана одно главное действие
   (Новая аренда, Оформить возврат, Импорт выписки) в фиксированной нижней панели над навигацией.
3. **Состояние — цвет + форма + слово.** Пять состояний мопеда и пять статусов аренды имеют
   закреплённые пары; иконка состояния одна и та же в списке, карточке и PDF.
4. **Один палец, один шаг.** Мастера выдачи и возврата: шаг = экран, «Далее» внизу, назад — свайп;
   поля с автофокусом, клавиатура нужного типа (телефон, число), VIN — сканер по умолчанию.
5. **Цифры не заставляют считать.** Показываем «оплачено по 19.09» и «долг 330 ₾», а не список
   счетов; список — на один уровень глубже.
6. **Пустое состояние — следующее действие.** «Просрочек нет» + «Загрузить выписку за сентябрь»;
   пустая таблица без подсказки — дефект.
7. **Лента вместо вкладок.** История мопеда и клиента — одна хронологическая лента событий с
   фильтром по типу, без переключения модулей.
8. **Поиск с первого символа.** Глобальный поиск по последним 4 знакам VIN, имени в любом
   написании, телефону и номеру аренды; результат группируется по типу.
9. **Ошибки говорят, что делать.** «Мопед в сервисе, выдача невозможна. Вернуть из сервиса?» с
   кнопкой, а не «недопустимое состояние».
10. **Всё, что печатается, в бренде.** Договор, акты, счёт — тот же логотип, типографика и цвет.

## Что улучшить относительно демо (реализовать на этапе 1–2)

| # | Где | Сейчас в демо | Стало |
|---|---|---|---|
| U1 | Сегодня | Шесть плиток одинакового веса | Первый ряд — действия дня (выдачи, возвраты, просрочки, неразобранные платежи) как задачи с кнопкой; плитки цифр — второй ряд, меньше |
| U2 | Сегодня | Список просрочек показывает сумму | Показывает дни просрочки и сумму, отсортировано по дням; у каждой строки действие «Напомнить» и «Отметить оплату» |
| U3 | Парк | Карточки по 4 в ряд, фильтр чипами | На телефоне — список с крупной строкой состояния и последними 4 знаками VIN; фильтр состояния — сегменты вверху, всегда видны; счётчик в сегменте |
| U4 | Парк, карточка | История без действий | Кнопка действия зависит от состояния: available → «Выдать», rented → «Возврат», service → «Вернуть в парк»; вторичные действия в меню |
| U5 | Аренды | Таблица с восемью колонками | На телефоне — карточки: имя, мопед, «оплачено по», долг, статус; таблица только ≥ 900 px; колонка «Долг» и «Статус» слиты в один pill |
| U6 | Аренда, карточка | Периоды списком | Полоса периодов: оплачен / текущий / просрочен, с датами; «оплачено по» крупно; действия внизу фиксированно |
| U7 | Платежи | Таблица платежей | Вкладки «Неразобранные» (по умолчанию, если есть) / «Все»; у неразобранного — подсказки «похоже на …» с кнопкой «Привязать» |
| U8 | Платежи | Импорт — модальное окно | Импорт — экран‑мастер: файл → предпросмотр разбора (сколько строк, сколько привязано автоматически) → подтверждение |
| U9 | Клиенты | Таблица | Карточка клиента с балансом первой строкой: «должен 330 ₾» / «переплата 20 ₾» / «нет долга»; кнопка WhatsApp рядом с именем |
| U10 | Сообщения | Шаблоны и очередь | Очередь как лента отправок со статусом доставки; ошибка доставки — красная строка с причиной и действием |
| U11 | Навигация | Боковая панель + нижняя на телефоне | Нижняя панель: Сегодня · Парк · Аренды · Платежи · Ещё; бейдж на «Сегодня» = число задач дня |
| U12 | Везде | Формы без проверки | Дубли клиента по телефону предлагаются до создания; VIN выбирается из парка, ввод текстом запрещён |
| ~~U13~~ | Везде | Только светлая тема | **Отменено Микой 14.09.2026.** Светлая остаётся единственной; тёмная тема не строится. Если вернётся — это второй набор значений в `packages/shared/tokens.json`, а не вторая таблица стилей |
| U14 | Везде | Латиница и грузинский вперемешку | Имя клиента в языке интерфейса первым, второе написание серым; сортировка по выбранному написанию |
| U15 | Печать | Нет | Договор, акты выдачи/возврата, счёт — PDF из тех же токенов, превью в карточке |
| U16 | Везде | Панели и меню появляются мгновенно | Всё, что приходит поверх страницы, приезжает с той стороны, которой принадлежит: панель справа — справа, лист на телефоне — снизу, меню строки — из точки нажатия. Длительность одна на всё — токен `--enter`; ховеры — `--ease`. При `prefers-reduced-motion` не движется ничего, и ничего не теряется: каждая анимация лишь повторяет то, что уже сказано словами |

## Проверка UX в приёмке этапа

- Kardu выполняет выдачу и возврат на тестовом стенде с телефона за ≤ 2 минуты без подсказок.
- Ни одного экрана без главного действия и без пустого состояния.
- Контраст ≥ 4.5:1 для текста, цели касания ≥ 44 px, грузинские имена рендерятся Noto Sans Georgian.
- Печать договора и актов из карточки с первого раза.
