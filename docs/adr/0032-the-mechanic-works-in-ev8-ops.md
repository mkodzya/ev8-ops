# 0032. Механик ведёт ремонт в EV8 Ops, бот механика остаётся только для уведомлений

Дата: 19.10.2026. Статус: **принято** 20.10.2026. Задачу поставил владелец 19.10.2026: «механик ведёт
ремонт в EV8 Ops с планшета мастерской вместо Telegram-бота»; 20.10.2026 он выбрал вариант ТЗ: «А:
заводим две новые роли — механик и главный механик, как в ТЗ и ADR-0033». Этап 0 плана
[`docs/spec/mechanic-in-erp-plan.md`](../spec/mechanic-in-erp-plan.md); ТЗ —
[`docs/spec/mechanic-in-erp.md`](../spec/mechanic-in-erp.md), сверка с кодом —
[`docs/spec/mechanic-in-erp-code.md`](../spec/mechanic-in-erp-code.md). Книга: реестр п. 88–91.

## Контекст

С 11.10.2026 работу механика учитывает Telegram-бот на Google Apps Script с Google-таблицей и
посредником Cloudflare. Копия кода как образец лежит на ветке `feature/mechanic-bot-prototype`
(`tools/mechanic-bot/`), в `develop` она не слита. Склад запчастей тоже ведётся в Google-таблице
`EV8_sklad_ucheta`, хотя склад в EV8 Ops собран (реестр книги п. 91): учёт двойной.

Утром 19.10.2026 в книге лёг первый вариант переноса (`notes/2026-10-19_mechanic-bot-in-ev8-ops.md`):
бот целиком переезжает в `apps/api` — публичный вебхук Telegram, диалог в базе, механик —
мастерская с Telegram ID, третьей роли нет. В тот же день директор написал ТЗ с другим ответом:
механик работает в самом EV8 Ops с планшета мастерской, а бот остаётся на время перехода и потом
только для уведомлений.

## Решение

1. **Ремонт ведётся в EV8 Ops.** Экраны ремонта — под планшет: крупные кнопки, камера для фото и
   QR; работают и на телефоне. Это доработка модуля ремонтов (`service_jobs`), а не новый модуль.
2. **Диалога с ботом в EV8 Ops нет.** EV8 Ops не принимает апдейты Telegram и не открывает
   публичный вебхук. Он только отправляет уведомления: заявка на согласование, заявка закрыта, пора на
   ТО, остаток ниже минимума — со ссылкой на заявку (этап 6). Отправляет API: токен лежит у него, а у
   воркера по устройству проекта секретов нет. О событиях API пишет в момент действия, по расписанию —
   когда воркер стучится в `/api/jobs/*`. Кнопки «согласовать»
   в Telegram ТЗ оставляет «по желанию»; если они понадобятся, это отдельное решение с публичным
   маршрутом и проверкой подписи.
3. **Переход — по шагам ТЗ:** пилот параллельно с ботом после этапа 4, переключение после этапа 6,
   затем уведомления. Бот выключает не сессия, а владелец и директор, когда выполнены критерии ТЗ.
4. **Токен бота и чат — у владельца**, в секретах сервера (правило 3), по образцу ключей банков и
   Kommo. Сейчас токен заведён на директора (реестр книги п. 90).
5. **Первый вариант 19.10.2026** (бот внутри `apps/api`, механик — мастерская с Telegram ID) этим
   заменён.

## Последствия

- В EV8 Ops не появляется публичный маршрут для Telegram: проверка гарда по маршрутам не меняется.
  Остаётся только исходящий вызов к API Telegram из `apps/api`.
- Пилот не требует нового сервера: тестовый и боевой стенды с HTTPS работают с 28.09.2026, планшет
  открывает их сразу.
- Механику нужен вход в EV8 Ops. Как он входит и какие у него права — ADR-0033.
- Пока идёт переход, ремонт ведётся в двух местах. Справочник работ и склад переносятся импортом
  (этапы 2 и 4); пока импорта нет, склад в EV8 Ops пуст.
- Таблицы бота и склада после переключения остаются архивом только для чтения; их ведёт директор,
  сессия их не трогает.
