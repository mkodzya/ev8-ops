# 0048. Меню начинается с дня, а менеджер разбирает деньги клиентов и звонит по графику

Дата: 25.10.2026. Статус: **принято** — запрос директора (Kardu) в GitHub issue `mkodzya/ev8-ops#15` от 25.10.2026,
подготовлен в его сессии, макет `menu-proposal.html` директор одобрил; Mika 25.10.2026: «начинай 15 и 16» — делать,
как просит директор. Ветка `feature/menu-and-manager-sort`, миграции нет. Дополняет навигацию волны 1 (§3.2–3.4) и
права ролей (redesign §2.1, Mika 17.09.2026); «Разобрать» по видам поступлений — ADR-0046, календарь оплат —
ADR-0016 и `docs/redesign/payments-calendar.md`. Ничего в них не переписывает.

## Контекст

Основная работа менеджера на месте — за ноутбуком: разносить поступления, звонить тем, кто просрочил или платит
сегодня, следить за парком. У менеджера не было ни календаря, ни «Разобрать»: оба стояли за `payments.view` /
`payments.reconcile`, из денег у него была только «Касса». У владельца календарь и «Разобрать» были вкладками
«Денег» — в два клика и без счётчиков в меню. Клиенты жили в меню аватара.

Ответы директора в issue: менеджер разносит **только платежи клиентов** — аренда, залог, продажа мопеда, товары,
ремонт и «Несколько услуг» из них; «Не наше», расходы, «Между счетами», «Взнос учредителя», прочий доход — владелец.
В календаре менеджер видит **только список, кто и сколько должен**, итогов недели и месяца в деньгах нет. Название —
«Оплаты по графику». Право и способ «решать тебе» — их выбрала сессия, ниже.

## Решение

### 1. Меню (`packages/shared/src/navigation.ts`)

| Группа | Раздел | Вкладки | Счётчик |
|---|---|---|---|
| **Ежедневно** | Сегодня | — | дела (серый) |
| | **Оплаты по графику** (`/schedule`) | Сегодня · Просрочки · Календарь; у владельца ещё «Месяц» | красный — аренд просрочено, серый — недель ждём сегодня |
| | **Разобрать** (`/sort`) | Поступления · Списания · Разобрано правилами · Убрано из очереди; у менеджера — только Поступления | строк в очереди (серый) |
| | Касса | Касса · Мои платежи — теперь и у владельца | — |
| **Парк** | Мопеды (было «Парк») | Мопеды · Модели · Точки · Батареи и зарядки | — |
| | **Аренды и клиенты** | Аренды · Клиенты (были в меню аватара) | — |
| | Ремонты (было «Сервис») | Ремонты · Склад · Справочник · К оплате | — |
| **Продажи и закупки** | Продажи | Мопеды · Товары | — |
| | Закупки (владелец) | Заказы · Поставщики | — |
| **Управление** (владелец) | Деньги | Платежи · Выписки · Залоги | — |
| | Отчёты · Настройки | как были | — |

Сверху на ноутбуке — «+ Действие» (открывает действия роли, как «+» на телефоне) и поиск. Телефон: нижняя панель
Сегодня · Оплаты · Разобрать · Мопеды · «Ещё»; в «Ещё» — остальные разделы роли в порядке меню (у менеджера Касса,
Аренды и клиенты, Ремонты, Продажи; у владельца ещё Закупки, Деньги, Отчёты, Настройки). «+» — круглая кнопка над
панелью справа, на списках разделов; в карточке и мастере её нет — там главное действие в липкой полосе снизу, и
кнопка легла бы на него; по той же причине её нет на Кассе, пока внизу полоса «Сдать N ₾». Подпись «Разобрать» на
панели по-грузински — короткое «გარჩევა» (`nav.sortShort`), как «Оплаты» у графика: «დასახარისხებელი» в пятую часть
экрана не помещается. Меню аватара — язык, «Мой вход», «Выйти».

Старые адреса работают: `/money/calendar` → `/schedule/calendar`, `/money/sort` → `/sort` (с `?d=out` →
`/sort/out`), `/money/sort/rules` и `/aside` → `/sort/…`, `/money` → `/money/payments`; запрос сохраняется
(`movedTo`).

### 2. Права (`packages/shared/src/permissions.ts`, `sort-rights.ts`)

Два новых права у владельца (у него все) и у менеджера:

- `payments.schedule` — «Оплаты по графику»: строки — кто, за какую неделю, сколько осталось; WhatsApp, звонок,
  «Провести вручную» (менеджеру форма денег по-прежнему даёт наличные).
- `payments.sort.customer` — «Разобрать» для денег клиентов.

| Что | Менеджер | Владелец |
|---|---|---|
| Оплаты по графику: строки, WhatsApp, звонок, «Провести вручную» | да | да |
| Итоги недели и месяца, сумма дня, «Пришло денег», долг всех просроченных вместе, вкладка «Месяц» | нет | да |
| Разобрать → Поступления: привязать к аренде (и неделе «до EV8 Ops»), залогу, продаже мопеда, товарам, ремонту или начислению | да | да |
| «Несколько услуг» из тех же записей; перенос дня оплаты в нём (право `rental.week.shift`, ADR-0041) | да | да |
| «Похоже, уже записан»: строку — к платежу аренды, продажи, ремонта, товаров, внесённому вручную | да | да |
| «Отвязать» деньги, которые он сам привязал из строки (страница платежа → «⋯») | да | да |
| Аванс клиента, сдача наличных в банк, новый штраф в «Нескольких услугах», «Запомнить для …» | нет | да |
| «Не наше», «Между счетами», «Взнос учредителя», прочий доход, «Убрать из очереди», «Вернуть», «Отвязать» чужого | нет | да |
| Списания, Разобрано правилами, Убрано из очереди, выписки, журнал платежей, залоги, отчёты, настройки | нет | да |

Аванс и сдача в банк в списке директора не названы — остаются у владельца. «Запомнить для …» — постоянное правило,
которое само разбирает следующие строки плательщика: его ставит владелец. Новый штраф — это начисление, решение
`deposit.decide`.

### 3. Сервер отказывает сам, по каждому маршруту

- `GET /api/money/calendar` — право `payments.schedule`. Без `payments.view` ответ — `scheduleOf(answer)`:
  строки (`entries`, `late.rentals`, карточки аренд), дни только со счётом оплат и состояний, недели только
  датами; `totals: false`. Поля перечислены по одному, без `...spread`: цифра, добавленная в календарь позже, не
  уйдёт менеджеру, пока её не впишут. Владельцу — весь ответ и `totals: true`.
- «Разобрать»: очередь, панель вариантов, `assign`, `split`, `link`, `unlink` — право `payments.sort.customer`;
  каждый отказывает менеджеру во всём, что не деньги клиентов, кодом `sort_owner_only` со словами. Менеджеру
  очередь отдаётся только входящими строками, без счётчиков владельца (`counts.out`, «правилами», «убрано» —
  `null`). Остальные ответы очереди — `payments.reconcile` по маршруту: менеджер до них не доходит вовсе.
  Списки маршрутов обоих новых прав держит `apps/api/test/guard.test.ts`.
- Счётчики — `GET /api/nav/counts`: «Оплаты по графику» — из того же ответа календаря за неделю сегодня
  (`scheduleCounts`), «Разобрать» — строки очереди (менеджеру входящие), касса — сданные наличные, ждущие
  владельца. Каждый — только тому, у кого есть раздел. Бейдж «Сегодня» по-прежнему из `/api/today`.

### 4. «Оплаты по графику» на экране

«Сегодня» — просроченные (старый долг сверху) и кто платит сегодня; «Просрочки» — весь список; «Календарь» — прежний
экран; у менеджера без карточки недели, без «Пришло денег» и без сумм в днях (в ячейке — число оплат). «Месяц» —
владельцу: цифры месяца и таблица по неделям; строка недели открывает календарь на этой неделе. Переключатель
«Неделя | Месяц» (директор, 22.10.2026) с экрана календаря ушёл во вкладку: два места про один вопрос — дефект
(ux №1).

### 5. «Разобрать» на экране

Под строкой менеджер видит только свои варианты; под ними тихо — «Аванс клиента, Сдача наличных в банк, Между
своими счетами, … — разбирает владелец». В «Нескольких услугах» нет аванса и штрафа. Галочки «Запомнить для …»
у менеджера нет.

## Последствия

- Менеджер звонит и разносит с ноутбука, не видя итогов недели и месяца; владелец видит всё, как раньше, в двух
  разделах вместо вкладок «Денег».
- Тест «менеджер не разносит строки банка» (`pay-day-in-sort.test.ts`) и тесты «календарь — только владельцу»
  (`calendar.test.ts`, `due-today.test.ts`) переписаны: менеджер теперь разносит деньги клиентов и получает
  строки календаря без сумм. Новые — `apps/api/test/manager-sort.test.ts`, `packages/shared/test/sort-rights.test.ts`,
  `packages/shared/test/schedule.test.ts`.
- Грузинские строки — `docs/qa/menu-and-manager-sort-ka-strings.md`, на вычитку Kardu.
- Открыто: нужен ли менеджеру аванс клиента; бейдж «Сегодня» стал серым, как в макете.
