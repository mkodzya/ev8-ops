# 0048. Меню начинается с дня, а менеджер разбирает деньги клиентов и звонит по графику

Дата: 25.10.2026. Статус: **принято** — запрос директора (Kardu) в GitHub issue `mkodzya/ev8-ops#15` от 25.10.2026,
подготовлен в его сессии, макет `menu-proposal.html` директор одобрил; Mika 25.10.2026: «начинай 15 и 16» — делать,
как просит директор. Ветка `feature/menu-and-manager-sort`, миграции нет. Дополняет навигацию волны 1 (§3.2–3.4) и
права ролей (redesign §2.1, Mika 17.09.2026); «Разобрать» по видам поступлений — ADR-0046, календарь оплат —
ADR-0016 и `docs/redesign/payments-calendar.md`. Ничего в них не переписывает.

## Контекст

Основная работа менеджера на месте — за ноутбуком: разносить поступления, звонить тем, кто просрочил или платит
сегодня, следить за парком. У менеджера не было ни календаря, ни «Разобрать»: оба стояли за `payments.view` /
`payments.reconcile`, из денег у него была только «Касса». У владельца календарь и «Разобрать» были вкладками
«Денег» — в два клика и без счётчиков в меню. Клиенты жили в меню аватара.

Ответы директора в issue: менеджер разносит **только платежи клиентов** — аренда, залог, продажа мопеда, товары,
ремонт и «Несколько услуг» из них; «Не наше», расходы, «Между счетами», «Взнос учредителя», прочий доход — владелец.
В календаре менеджер видит **только список, кто и сколько должен**, итогов недели и месяца в деньгах нет. Название —
«Оплаты по графику». Право и способ «решать тебе» — их выбрала сессия, ниже.

## Решение

### 1. Меню (`packages/shared/src/navigation.ts`)

| Группа | Раздел | Вкладки | Счётчик |
|---|---|---|---|
| **Ежедневно** | Сегодня | — | дела (серый) |
| | **Оплаты по графику** (`/schedule`) | Сегодня · Просрочки · Календарь; у владельца ещё «Месяц» | красный — аренд просрочено, серый — недель ждём сегодня |
| | **Разобрать** (`/sort`) | Поступления · Списания · Разобрано правилами · Убрано из очереди; у менеджера — только Поступления | строк в очереди (серый) |
| | Касса | Касса · Мои платежи — теперь и у владельца | — |
| **Парк** | Мопеды (было «Парк») | Мопеды · Модели · Точки · Батареи и зарядки | — |
| | **Аренды и клиенты** | Аренды · Клиенты (были в меню аватара) | — |
| | Ремонты (было «Сервис») | Ремонты · Склад · Справочник · К оплате | — |
| **Продажи и закупки** | Продажи | Мопеды · Товары | — |
| | Закупки (владелец) | Заказы · Поставщики | — |
| **Управление** (владелец) | Деньги | Платежи · Выписки · Залоги | — |
| | Отчёты · Настройки | как были | — |

Сверху на ноутбуке — «+ Действие» (открывает действия роли, как «+» на телефоне) и поиск. Телефон: нижняя панель
Сегодня · Оплаты · Разобрать · Мопеды · «Ещё»; в «Ещё» — остальные разделы роли в порядке меню (у менеджера Касса,
Аренды и клиенты, Ремонты, Продажи; у владельца ещё Закупки, Деньги, Отчёты, Настройки). «+» — круглая кнопка над
панелью справа, на списках разделов; в карточке и мастере её нет — там главное действие в липкой полосе снизу, и
кнопка легла бы на него; по той же причине её нет на Кассе, пока внизу полоса «Сдать N ₾». Подпись «Разобрать» на
панели по-грузински — короткое «გარჩევა» (`nav.sortShort`), как «Оплаты» у графика: «დასახარისხებელი» в пятую часть
экрана не помещается. Меню аватара — язык, «Мой вход», «Выйти».

Старые адреса работают: `/money/calendar` → `/schedule/calendar`, `/money/sort` → `/sort` (с `?d=out` →
`/sort/out`), `/money/sort/rules` и `/aside` → `/sort/…`, `/money` → `/money/payments`; запрос сохраняется
(`movedTo`).

### 2. Права (`packages/shared/src/permissions.ts`, `sort-rights.ts`)

Два новых права у владельца (у него все) и у менеджера:

- `payments.schedule` — «Оплаты по графику»: строки — кто, за какую неделю, сколько осталось; WhatsApp, звонок,
  «Провести вручную» (менеджеру форма денег по-прежнему даёт наличные).
- `payments.sort.customer` — «Разобрать» для денег клиентов.

| Что | Менеджер | Владелец |
|---|---|---|
| Оплаты по графику: строки, WhatsApp, звонок, «Провести вручную» | да | да |
| Итоги недели и месяца, сумма дня, «Пришло денег», долг всех просроченных вместе, вкладка «Месяц» | нет | да |
| Разобрать → Поступления: привязать к аренде (и неделе «до EV8 Ops»), залогу, продаже мопеда, товарам, ремонту или начислению | да | да |
| «Несколько услуг» из тех же записей; перенос дня оплаты в нём (право `rental.week.shift`, ADR-0041) | да | да |
| «Похоже, уже записан»: строку — к платежу аренды, продажи, ремонта, товаров, внесённому вручную | да | да |
| «Отвязать» деньги, которые он сам привязал из строки (страница платежа → «⋯») | да | да |
| Аванс клиента, сдача наличных в банк, новый штраф в «Нескольких услугах», «Запомнить для …» | нет | да |
| «Не наше», «Между счетами», «Взнос учредителя», прочий доход, «Убрать из очереди», «Вернуть», «Отвязать» чужого | нет | да |
| Списания, Разобрано правилами, Убрано из очереди, выписки, журнал платежей, залоги, отчёты, настройки | нет | да |

Аванс и сдача в банк в списке директора не названы — остаются у владельца. «Запомнить для …» — постоянное правило,
которое само разбирает следующие строки плательщика: его ставит владелец. Новый штраф — это начисление, решение
`deposit.decide`.

### 3. Сервер отказывает сам, по каждому маршруту

- `GET /api/money/calendar` — право `payments.schedule`. Без `payments.view` ответ — `scheduleOf(answer)`:
  строки (`entries`, `late.rentals`, карточки аренд), дни только со счётом оплат и состояний, недели только
  датами; `totals: false`. Поля перечислены по одному, без `...spread`: цифра, добавленная в календарь позже, не
  уйдёт менеджеру, пока её не впишут. Владельцу — весь ответ и `totals: true`.
- «Разобрать»: очередь, панель вариантов, `assign`, `split`, `link`, `unlink` — право `payments.sort.customer`;
  каждый отказывает менеджеру во всём, что не деньги клиентов, кодом `sort_owner_only` со словами. Менеджеру
  очередь отдаётся только входящими строками, без счётчиков владельца (`counts.out`, «правилами», «убрано» —
  `null`). Остальные ответы очереди — `payments.reconcile` по маршруту: менеджер до них не доходит вовсе.
  Списки маршрутов обоих новых прав держит `apps/api/test/guard.test.ts`.
- Счётчики — `GET /api/nav/counts`: «Оплаты по графику» — из того же ответа календаря за неделю сегодня
  (`scheduleCounts`), «Разобрать» — строки очереди (менеджеру входящие), касса — сданные наличные, ждущие
  владельца. Каждый — только тому, у кого есть раздел. Бейдж «Сегодня» по-прежнему из `/api/today`.

### 4. «Оплаты по графику» на экране

«Сегодня» — просроченные (старый долг сверху) и кто платит сегодня; «Просрочки» — весь список; «Календарь» — прежний
экран; у менеджера без карточки недели, без «Пришло денег» и без сумм в днях (в ячейке — число оплат). «Месяц» —
владельцу: цифры месяца и таблица по неделям; строка недели открывает календарь на этой неделе. Переключатель
«Неделя | Месяц» (директор, 22.10.2026) с экрана календаря ушёл во вкладку: два места про один вопрос — дефект
(ux №1).

### 5. «Разобрать» на экране

Под строкой менеджер видит только свои варианты; под ними тихо — «Аванс клиента, Сдача наличных в банк, Между
своими счетами, … — разбирает владелец». В «Нескольких услугах» нет аванса и штрафа. Галочки «Запомнить для …»
у менеджера нет.

## Последствия

- Менеджер звонит и разносит с ноутбука, не видя итогов недели и месяца; владелец видит всё, как раньше, в двух
  разделах вместо вкладок «Денег».
- Тест «менеджер не разносит строки банка» (`pay-day-in-sort.test.ts`) и тесты «календарь — только владельцу»
  (`calendar.test.ts`, `due-today.test.ts`) переписаны: менеджер теперь разносит деньги клиентов и получает
  строки календаря без сумм. Новые — `apps/api/test/manager-sort.test.ts`, `packages/shared/test/sort-rights.test.ts`,
  `packages/shared/test/schedule.test.ts`.
- Грузинские строки — `docs/qa/menu-and-manager-sort-ka-strings.md`, на вычитку Kardu.
- Открыто: нужен ли менеджеру аванс клиента; бейдж «Сегодня» стал серым, как в макете.

## Дополнение 25.10.2026: менеджер нигде не видит денег всех клиентов вместе

**Откуда.** QA-обход #15 и #16 (25.10.2026) нашёл: «Оплаты по графику» скрывают от менеджера долг всех просроченных
вместе (§2, §3), а в других местах он его видит — на «Сегодня» строка вида «Ещё 9 · 12 345 ₾» под группой
«Просрочено» (→ `/rentals?s=overdue`), в «Арендах» — «40 аренд · долг 23 456 ₾». Это не #15, так было и раньше.
Там же: «Ещё 9» стояло рядом с суммой по всем 12 должникам, а не по 9 оставшимся. Сессия спросила Mika, скрывать ли.
Цифры в этом дополнении — выдуманные примеры: репозиторий публичный, а настоящие суммы всех долгов вместе — те самые,
которые теперь не видит даже менеджер.

**Решение.** Mika, 25.10.2026: «да» — скрыть от менеджера всякую цифру, которая складывает долг или деньги всех клиентов
вместе, как это уже делают «Оплаты по графику». Ветка `feature/manager-no-totals`, миграции нет. Правила §1–5 выше
остаются; это дополнение распространяет строку таблицы §2 «Итоги … долг всех просроченных вместе — нет / да» на все
экраны и ответы, до которых менеджер доходит.

1. **Правило одно.** Сумму многих клиентов вместе читает тот, кто читает «Деньги» (`payments.view`) — то же право, что
   держит итоги недели и месяца календаря. `seesTotals` в `packages/shared/src/permissions.ts`, на сервере —
   `mayTotal(req)` в `apps/api/src/lib/guard.ts`. Цифра одного клиента, одной аренды, одной продажи, одной строки
   остаётся у всех.
2. **Сервер не присылает.** Поле суммы менеджеру уходит `null`, экран рисует только то, что пришло:

   | Ответ | Что вырезано у менеджера | Что остаётся |
   |---|---|---|
   | `GET /api/today` | `queue[].totalTetri` — сумма группы («Просрочено», «Ждём сегодня» и других) | строки со своей суммой; `numbers.overdueTetri`, залоги и неделя были владельца и раньше |
   | `GET /api/rentals` | `totals: false` — список не складывает долги строк | «40 аренд», долг каждой аренды |
   | `GET /api/sales` | `overdueTetri` — просрочка всех покупателей | просрочка каждой продажи |
   | `GET /api/goods-sales` | `openTetri` — сколько ждут все продажи товаров | «Ждут оплаты 3», остаток каждой продажи |
   | `GET /api/summary` | `salesOverdueTetri` | строки просрочек со своим долгом |
   | `GET /api/payments` без записи | `totals` — «Пришло / Ушло / Комиссия» по «Моим платежам» (с #15 там и строки банка, которые он разнёс) | суммы платежей одного клиента, аренды, продажи (`customerId`, `rentalId`, `saleId`, `goodsSaleId`) |

   Не тронуто: его касса — наличные у него на руках, которые он сдаёт («Моя касса» на «Сегодня», `GET /api/till`):
   это его собственная работа, без неё «Сдать N ₾» не нажать. Счётчики (`/api/nav/counts`, число просрочек, строк
   «Разобрать») — числа, не деньги. Поиск, карточки клиента, аренды, продажи, «Клиенты», «Мопеды» сумм нескольких
   клиентов не показывали.
3. **Число и сумма — об одном наборе** (для владельца). Под группой «Сегодня» с суммой — «Все 12 · 12 345 ₾»: все строки
   группы и их деньги, та же цифра, из которой сложен список, куда ведёт ссылка (ux №10). Группа без суммы и группа
   менеджера — по-прежнему «Ещё 9». Выбор строки — `queueMore` в `packages/shared/src/today.ts`.
4. **Тесты.** `apps/api/test/manager-no-totals.test.ts` — по каждому ответу: менеджер получает `null` (или
   `totals: false`), владелец — цифру; `packages/shared/test/due.test.ts` — очередь «Сегодня» для обоих и группа из пяти
   строк: под ней у владельца «Все 5 · …», у менеджера «Ещё 2» (`queueMore`); `apps/api/test/due-today.test.ts` — менеджер больше не получает сумму группы владельца.

**Там же — мелкие находки QA-обхода** (умолчания сессии):

- «Разобрать», «Похоже, уже записан»: у кандидата — вид платежа (`paymentKind`), экран спрашивает `mayLinkPayment`, то же
  правило, по которому отказывает `/link`. Менеджеру к авансу клиента, внесённому вручную, «Да, это он» не предлагается:
  видно, что деньги уже записаны, и рядом — «Аванс клиента — разбирает владелец».
- Меню на ноутбуке — 270 px, как в макете директора (было 220): «Оплаты по графику» с двумя счётчиками в одну строку,
  грузинское «დასახარისხებელი» больше не рвётся посреди слова.
- Заголовки `/fleet` и `/service` — словами меню: «Мопеды» и «Ремонты» (`nav.fleet`, `nav.service`), не «Парк» и
  «Сервис».
- Группа меню у менеджера — «Продажи», а не «Продажи и закупки»: внутри у него только «Продажи» (`groupHeadingFor`).
- Короткое «გარჩევა» на панели телефона против «დასახარისხებელი» в меню — решение §1 выше, не правится; вопрос
  Kardu — в `docs/qa/manager-no-totals-ka-strings.md`.

## Дополнение 28.10.2026: «Склад» — раздел меню

**Откуда.** GitHub issue `mkodzya/ev8-ops#19` директора (27–28.10.2026), п. 1: запчасти были вкладкой «Ремонты → Склад»
(`/service/stock`), батареи и зарядки — вкладкой «Мопеды → Батареи и зарядки» (`/fleet/batteries`). 28.10 директору
понадобилось продать запчасть (продажа товаров, issue #11, ADR-0045), и склада он не нашёл: искал его в «Закупках».
Mika 28.10.2026: «А» — брать #19 сейчас, после #17; место в меню — на его усмотрение, ниже — умолчания сессии. Ветка
`feature/issue-19-stock-section-and-two-fixes`, миграции для меню нет.

**Решение.** Таблица §1 меняется в трёх строках, остальное остаётся:

| Группа | Раздел | Вкладки | Счётчик |
|---|---|---|---|
| **Парк** | Мопеды | Мопеды · Модели · Точки | — |
| | Ремонты | Ремонты · Справочник · К оплате | — |
| **Продажи и закупки** | Продажи | Мопеды · Товары | — |
| | **Склад** (`/stock`) | **Запчасти** (`/stock`) · **Батареи и зарядки** (`/stock/batteries`) | — |
| | Закупки (владелец) | Заказы · Поставщики | — |

1. **Место** (умолчание сессии): внутри «Продажи и закупки», между «Продажами» и «Закупками». Склад — то, с чего
   продают и что наполняют заказы; директор искал его рядом с ними. Отдельной группы не заводим: в ней был бы один раздел.
2. **Права — как у вкладок до этого**: раздел и обе вкладки — `fleet.view`, то есть у владельца и менеджера. У механика
   и главного механика раздела нет, как не было вкладки: детали они пишут в карточке ремонта (ADR-0036), а на маршруты
   склада права не менялись.
3. **Заголовок группы у менеджера** — «Продажи и склад» (`salesStock`, `groupHeadingFor`): правило QA #15 — заголовок
   говорит, что под ним, — а под ним у менеджера теперь «Продажи» и «Склад». У владельца — по-прежнему «Продажи и закупки».
4. **Страница** называется словом меню — «Склад» (`nav.stock`), под ней вкладки «Запчасти · Батареи и зарядки»; у
   батарей и зарядок заголовок свой, как был («Батареи» / «Зарядки»). Прежние «Склад» (`shelf.title`, `stock.nav`) и
   английское «Warehouse» убраны: у раздела одно слово — «Склад» / «საწყობი» / «Stock».
5. **Телефон**: на нижней панели ничего не меняется; в «Ещё» «Склад» стоит после «Продаж» (у менеджера — Касса, Аренды и
   клиенты, Ремонты, Продажи, Склад; у владельца за ним Закупки, Деньги, Отчёты, Настройки). Счётчика у раздела нет.
6. **Старые адреса ведут на новые**, запрос сохраняется (`movedTo`): `/service/stock` → `/stock` (с `?f=short`),
   `/service/stock/parts/:id` → `/stock/parts/:id`, `/fleet/batteries` → `/stock/batteries` (с `?item=charger`). Прежние
   переадресации `/stock` → `/service/stock` и `/stock/parts/:id` → `/service/stock/parts/:id` сняты: `/stock` теперь адрес

## Дополнение 28.10.2026: упрощения по аудиту (issue #18, часть B)

**Откуда.** GitHub issue `mkodzya/ev8-ops#18` директора (25.10.2026): перед разделом «Задачи» — аудит всей навигации
(`navigation.ts`, `permissions.ts`, словари, страницы) и чтение боевого (только GET), директор согласовал все пункты
B1–B8. Mika 28.10.2026: «А» — сначала #17 и #19, потом #18 частями (сначала упрощения B, затем «Задачи» A); на B8 —
«Да, без отмены»; на B4 — «Одно правило календаря». Ветка `feature/issue-18-b-simplify`, миграции нет. Часть A
(«Задачи») здесь не делается.

**Решение.** Таблица §1 и права §2 меняются так; остальное остаётся.

1. **B1 — одна подпись у одной формы денег.** Везде «Принять оплату»; у кого нет `payments.reconcile` — «Принять
   наличные»: «+», сама форма, шапка аренды, возврат и выдача с долгом (с суммой: «Принять оплату 330»), строка
   «Оплат по графику» (было «Провести вручную»), продажа товаров, подсказки, которые называют форму. В карточке
   аренды кнопка одна — в шапке; у блока платежей второй больше нет. Ключи «Записать платёж» / «Провести платёж»,
   которые не читал ни один экран, удалены.
2. **B2 — выдача, возврат, замена одними словами.** «Выдать мопед» (было «Новая выдача», «Оформить выдачу», «Завести
   аренду»), «Вернуть мопед» (было «Принять возврат», голое «Возврат»), «Заменить мопед». В «+» — новый пункт
   **«Заменить мопед»** (`swap`, `/rentals/swap`): идущие аренды с мопедом, поиск по имени, телефону, VIN, затем
   мастер замены ADR-0040. Нужны оба права, как в «⋯» карточки, — `rental.create` и `rental.return`; у действий
   навигации для этого появилось `allOf`. Менеджеру пункт доступен.
3. **B5 — одно понятие, одно слово** (и `scripts/words-guard.mjs` это держит): ремонты — «Ремонты», статус мопеда —
   «В ремонте» (было «Сервис», «в сервисе»); группа «Решения» на «Сегодня» влита в «Дозаполнить» (рядом с «Решить»
   она читалась её двойником); деньги клиента без аренды — «Аванс клиента» (было и «Аванс по аренде»); наличные в
   банк — «Внесение наличных в банк» («сдача» — слово кассы); одна строка банка на несколько записей — «Несколько
   услуг» и для поступлений, и для списаний (было «Разнести»); товары — «Товары» (было «Товары / запчасти»); первая
   вкладка «Оплат по графику» — «К звонку», а не второе «Сегодня»; в «Настройках» — «Статьи расходов» и «Статьи
   доходов», вкладки со своими id (`expenseItems`, `incomeItems`), а «Поступления» остаются у «Разобрать» и у
   отчёта. По-грузински новых слов для старых понятий нет: девять строк переведены на слово, которое у понятия уже
   было у Kardu (список ему на проверку — §2 `docs/qa/issue-18-b-simplify-ka-strings.md`); где у одного понятия два
   грузинских слова, ветка их не трогает и спрашивает его (§3 там же).
4. **B6 — лишние места у владельца.** «Касса → Мои платежи» у того, кто читает «Деньги → Платежи», не показывается
   (`noneOf: ['payments.view']`), у менеджера остаётся. «Точки» — только «Мопеды → Точки»: вкладка в «Настройках»
   снята, `/settings/points` ведёт туда (`REDIRECTS`). Мопеды «В ремонте» без открытой заявки (на боевом 25.10 — 19)
   ушли из «Настройки → До EV8 Ops» блоком «В ремонте без заявки» в «Ремонты» — под списком ремонтов, свёрнутым в
   одну строку «В ремонте без заявки · N мопедов», на телефоне мопед — строка, кнопки под ним; для того, кто двигает
   мопед руками (`fleet.state.manual`: владелец и менеджер): открыть ремонт или вернуть мопед в парк с причиной
   (`GET /api/service/without-repair`, `POST /api/service/without-repair/:id/back`). Вкладка «До EV8 Ops» рисуется,
   только пока в её двух списках что-то есть: `/api/nav/counts` несёт `migration`, `tabsShown` прячет вкладку на нуле
   — но не до прихода чисел и не когда она открыта. Kommo и Drive не тронуты.
5. **B4 — «Сегодня»:** вместо групп «Просрочены» и «Ждём сегодня» одна строка «Оплаты: N просрочено · M сегодня» в
   `/schedule`; правило просрочки у всех списков — расписания (ADR-0016, дополнение того же дня). Счётчик «Сегодня»
   считает эту строку за одно дело: людей считает счётчик «Оплат по графику».
6. **B7 — деньги недели в одном месте.** Карточка «Неделя» и плитка «за неделю» с «Сегодня» сняты: они повторяли

   недели — «Отчёты → Неделя»»; API их больше не считает.
7. **B8 — менеджер продаёт мопеды**: право `sales.create`, отмена, обратный выкуп и дата — у владельца (ADR-0045,
   дополнение того же дня). В «+» у менеджера — «Продать мопед».
