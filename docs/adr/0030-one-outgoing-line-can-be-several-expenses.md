# 0030. Одно списание — несколько расходов

Дата: 19.10.2026. Статус: принято разработкой по задаче владельца; в `develop` и на тестовом стенде, на боевой
— по слову Mika. Mika 19.10.2026: «нужно добавить возможность разделить платеж расходный на части».
Дополняет [ADR-0027](0027-money-going-out-says-what-it-was-for.md) так же, как
[ADR-0019](0019-one-bank-line-can-pay-several-records.md) дополнял разбор приходов; ничего не отменяет.

## Контекст

Списание получало одну категорию (ADR-0027). Один платёж со счёта нередко оплачивает несколько вещей сразу —
например, два налога одним переводом в казну, — и тогда в отчёте всё попадало в одну категорию.

## Решение

1. **«Разделить» в панели «Расход ▸»** рядом с «Записать». Окно — строки «категория · сумма», от двух до
   девяти; пустая сумма при касании берёт остаток; внизу — сколько ещё разнести или на сколько больше строки.
   Одна категория — одна часть.
2. **Части вместе — вся сумма строки**; иначе сервер отказывает (`split_sum`), как при разделе прихода.
   Ошибки те же, что у раздела прихода: `split_needs_two`, `split_too_many`, `split_same_target`.
3. **Хранение.** Строка — «расход компании» без своей категории, части — в `statement_line_expense_parts`
   (миграция 0050: строка, номер части, сумма, категория). `POST /api/statement-lines/:id/expense-split`; в
   журнале — `statement.line.expense_split` с частями.
4. **Отчёт «Расходы»** считает каждую часть в её категории. **«Отложено»** показывает «Расход компании
   частями: Налоги 300.00 ₾ · Охрана 200.00 ₾». **«Вернуть в очередь»** возвращает строку целиком, части
   удаляются.
5. Получатель при разделе не запоминается: следующий платёж ему может делиться иначе.

## Последствия

- Отчёт по категориям верен и для платежей, оплативших несколько вещей.
- Части — только категории расходов. Если в одном списании и расход, и вывод акционера, такое пока делится
  только целиком на что-то одно.
