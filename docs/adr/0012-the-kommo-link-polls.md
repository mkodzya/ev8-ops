# 0012. Связь с Kommo опрашивает, а не ждёт вебхуков

Дата: 07.10.2026. Статус: принято (Mika поставил задачу на шаг 1 связи 07.10.2026;
способ — опрос — выбран сессией по факту тарифа).

## Контекст

С 07.10.2026 Kommo — источник правды для ежедневной работы (handoff §2а): кто
на каком мопеде и кто сколько заплатил, записано там. EV8 Ops наполняется
слоями, и пока идёт перенос, две системы должны сходиться — а где не
сходятся, владелец должен это видеть, а не узнавать случайно.

Обычный способ узнавать о переменах в Kommo — вебхуки: Kommo сам сообщает, что
сделка сменила этап. Что проверено в аккаунте `ev8mopeds.kommo.com` 07.10.2026:

- **Тариф — Base.** Вебхуки на нём недоступны (нужен Advanced и выше). До сих
  пор двусторонняя связь в продукте откладывалась «до тарифа с вебхуками»
  (реестр книги, п. 5).
- **Приватная интеграция с долгосрочным токеном на Base работает:** Settings →
  Integrations → Create integration → Keys and scopes → Generate long-lived
  token. Доступ — уровня администратора, срок — до пяти лет.
- **Лимит API — 7 запросов в секунду** на аккаунт.
- **Воронка аренды** — «Gaqiraveba», id 13427775. Этап «გაქირავებული» (в
  аренде) — id 103582579, в нём 07.10.2026 стояло 17 сделок. Другие этапы:
  бронь 107998668, лист ожидания 106655276, закрыта 142, «больше не хочет» 143.
- **Оплаты аренды** сотрудники пишут свободным текстом — заметками к сделке.
- REST v4: `GET /api/v4/leads?with=contacts&filter[statuses][0][pipeline_id]=…&filter[statuses][0][status_id]=…`,
  `GET /api/v4/leads/{id}/notes`, заголовок `Authorization: Bearer …`; пустой
  результат — HTTP 204 без тела; страница — не больше 250 записей.

Чего проверить было нельзя: токена на момент решения не существовало, поэтому
ни один запрос к API с настоящим токеном не выполнялся. Что Base не откажет
приватной интеграции в самих вызовах API, известно из документации и экрана
настроек, а не из ответа сервера.

## Решение

**Связь опрашивает.** Раз в пять минут EV8 Ops сам спрашивает Kommo, какие
сделки стоят в этапе аренды, и хранит последний ответ. Перехода на тариф с
вебхуками связь не ждёт и от него не зависит.

Шаг 1 — только чтение и сверка:

1. **Клиент** (`apps/api/src/lib/kommo.ts`). Один вход во внешний сервис: в нём
   токен, пауза между запросами (не чаще одного в 160 мс — под лимит 7 в
   секунду с запасом) и перевод отказов в свои слова: `unauthorized`,
   `rate_limited`, `http`, `network`, `bad_answer`. HTTP 204 — «сделок нет», не
   ошибка. Постранично по 250. Сделка чужого этапа отбрасывается, даже если
   Kommo проигнорировал фильтр. Имена основных контактов берутся вторым
   запросом пачкой; если он не удался, сделки всё равно сохраняются.
2. **Часы — воркер, работа — в API.** Воркер по расписанию `KOMMO_CRON`
   (`*/5 * * * *`) стучит в `POST /api/jobs/kommo-sync` своим токеном, как и в
   ночной прогон недель. Сам опрос идёт в API: там и токен Kommo, и база. У
   воркера нет ни того, ни другого, и секрет живёт в одном процессе.
3. **Снимок** (миграция 0032). `kommo_leads` — сделки этапа аренды по
   последнему удачному опросу: id сделки, её название, имя контакта, когда
   увидена впервые и в последний раз. `kommo_sync` — одна строка: когда Kommo
   ответил в последний раз, когда его спрашивали и каким словом кончилась
   неудача. **Неудачный опрос снимок не трогает.**
4. **Сверка** (`packages/shared/src/kommo.ts`, без сети и базы). Сделка
   находит аренду по ссылке Kommo на самой аренде, а если её там нет — по
   ссылке на клиенте аренды. Расхождений два вида: в Kommo в аренде, а
   действующей аренды здесь нет; здесь аренда действует, а сделка в Kommo не в
   этапе аренды — или ссылки на Kommo нет вовсе. Действующая — выданная и не
   возвращённая; бронь не в счёт, у неё в Kommo свой этап.
5. **Экран.** Владельцу — одна строка в «Сегодня» (группа «Решения») и список
   за ней, `/settings/kommo`: оба вида расхождений, с переходом в Kommo и в
   карточку или аренду здесь, и время ответа Kommo. Менеджер не видит ни
   строки, ни списка. Если Kommo молчит дольше двадцати минут, строка
   появляется и без расхождений — «Kommo не отвечает»: отсутствие строки не
   должно читаться как «всё сошлось». Пока Kommo не ответил ни разу, ничего не
   сравнивается.
6. **Токен** — секрет сервера (CLAUDE.md, правило 3). Его выпускает Mika и сам
   кладёт на стенд: `deploy/set-kommo-token.sh`. Через сессию, коммит, лог и
   аргументы команд он не проходит. Ответы Kommo в логи тоже не пишутся: в них
   имена. **Без токена связь выключена целиком и молча** — ни строки, ни
   списка, ни запросов наружу.

Адрес аккаунта и id воронки и этапа — настройки (`KOMMO_BASE_URL`,
`KOMMO_RENTAL_PIPELINE_ID`, `KOMMO_RENTED_STATUS_ID`); значения этого аккаунта
стоят умолчаниями в одном месте, в клиенте. Токен уходит только на https-адрес.

**Чего в шаге 1 нет, и где оно встанет.** В Kommo ничего не пишется. Запись
оплаты заметкой к сделке и перевод сделки на другой этап — следующие шаги;
они пойдут через тот же вход клиента (`request`), своим методом каждый, и для
них понадобится журнал того, что отправлено. Строка снимка уже хранит id
этапа — чтобы читать и другие этапы, не меняя таблицу.

## Последствия

- Перемена в Kommo видна здесь с задержкой до пяти минут, а не сразу. Для
  сверки «кто в аренде» этого хватает; для шага, где важна минута, цифра в
  расписании меняется одной строкой.
- Нагрузка — два-три запроса раз в пять минут, далеко от лимита.
- Долгосрочный токен даёт интеграции права администратора на весь аккаунт
  Kommo до пяти лет. Он лежит только в env-файле стенда (режим 600); отзыв —
  генерацией нового в Kommo. Срок токена кончится молча: это будет видно как
  «Kommo не отвечает» в «Сегодня», а скрипт на отказ отвечает прямо.
- Поле Kommo на клиенте, аренде и продаже было ссылкой «чтобы открыть».
  Теперь по нему идёт сверка: аренда без ссылки попадает в расхождения, и это
  повод её вписать. Подсказка у поля всё ещё говорит «до тарифа с вебхуками» —
  текст устарел, поправить отдельно.
- На тестовом стенде при включении ожидается 17 расхождений вида «в Kommo в
  аренде, здесь аренды нет»: аренды ещё не введены (слой 3). По мере ввода
  число идёт к нулю — это и есть счётчик переноса.
- Если Base всё же откажет приватной интеграции в вызовах API с настоящим
  токеном, шаг 1 останется выключенным без вреда, а решение придётся
  пересмотреть: тариф или выгрузка из Kommo вручную.
- П. 5 реестра книги («Kommo: тариф с вебхуками») для сверки больше не
  блокирует; для связи в обе стороны его нужно переоценить отдельно.
