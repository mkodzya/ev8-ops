# Инженерные практики EV8 Ops — что берём у студии и из клиентских проектов

Свод на 14.09.2026. Источник каждой практики указан: книга студии (`selfstudio-tech/handbook`,
ADR‑0003…0010) или книга клиента (Kultura, Tuff Stuff, Nichebox, APECS, PSP). EV8 — не проект
студии, поэтому берём инженерный протокол и проверенные решения, а не формат книги.
Секреты из книг клиентов сюда не переносятся никогда.

## 1. Репозиторий и сессии (студия, ADR‑0006…0010)

| Практика | Как в EV8 Ops | Источник |
|---|---|---|
| GitFlow | `develop` — работа и default; `main` — релизы с тегом голого semver `X.Y.Z`; `feature/<topic>` от develop, `hotfix/<topic>` от main; влитые ветки удаляются, невлитые архивируются тегом `archive/<branch>-<date>` | ADR‑0007, Kultura ADR‑0012 |
| Одна копия — один писатель | Основной checkout на `develop` всегда чист. Каждая задача — worktree `../_worktrees/ev8-ops-<topic>` на своей ветке; в чужом worktree ничего не правим | ADR‑0008 |
| Старт сессии | `git status`, `git log -3`; чужие незакоммиченные правки не трогать, о них — в отчёте | ADR‑0006 |
| Коммит и push по ходу | Каждая законченная правка — коммит сразу и push тем же шагом; сессия не заканчивается с незапушенным; заголовок коммита — фраза‑вердикт в стиле NYT («The Rental Period Is Born at Pickup, Not at Import») | ADR‑0009 |
| Только адресные правки | Edit нужного места, никаких tar/rsync поверх рабочей копии; `push --force` и `reset --hard` — никогда | ADR‑0006 |
| Без личных данных в репозитории | Ни телефонов клиентов, ни личных номеров, ни снимков Odoo, ни выписок. Живут в `~/Desktop/EV8-ops/` | ADR‑0009 |
| Тяжёлые задачи под бюджет | Mac 8 ГБ: одна тяжёлая задача на машину; `NODE_OPTIONS=--max-old-space-size=…`, `--maxWorkers=2` или `--runInBand`, `nice -n 10`, явный таймаут; второй запуск, пока судьба первого неизвестна, запрещён; `docker compose up`, Vite build, Prisma generate, Playwright — тяжёлые | ADR‑0010, Tuff Stuff runbook 10.09 |
| Классификатор auto‑режима | Длинные git‑цепочки с `--force`, `-D`, `rm -rf` блокируются — шаги мелкие | knowledge.md студии |
| Не проверять имя до записи | DNS‑проверку новой записи делать мимо системного кэша (DoH), иначе NXDOMAIN кэшируется на час | studio gotcha 14.09 |

## 2. Поставка и стенды (Kultura, Tuff Stuff)

| Практика | Как в EV8 Ops | Источник |
|---|---|---|
| Деплой — push тега, тесты гейтят | Прод собирается только по тегу `X.Y.Z` на `main` через `workflow_dispatch` + guard на голый semver; красные тесты физически не доезжают до образа; история прода = список тегов, откат = прогон предыдущего | Kultura ADR‑0009, ADR‑0012 |
| develop — это stage | Тестовый стенд крутит `develop`, прод — тег; прод наполняется копией данных с тестового, а не сидом, когда стенд стал рабочим инструментом | Kultura ADR‑0013 |
| Один VM, один Traefik, compose‑проекты на общей docker‑сети | Один сервер на test и prod (как у Self Platform): Traefik терминирует TLS, контейнеры на внутренней сети, наружу только 80/443; Postgres на loopback; минимум 2 vCPU / 2 ГБ | Kultura ADR‑0008, Tuff Stuff infrastructure.md |
| Админка — источник правды, сид не перезаписывает | Сид только для пустой базы; загрузка справочников заполняет пустые поля и никогда не трогает введённое пользователем; `--overwrite` только для чистого стенда с предупреждением | Kultura ADR‑0011 |
| Внешняя копия вне облака | Снимки диска ежедневно у провайдера + месячная копия `pg_dump -Fc` и медиа на внешний диск, шифрование gpg, `SHA256SUMS`, и обязательная проверка, что дамп восстанавливается; урок: 07.09.2026 у провайдера кончились деньги и прод лёг вместе с dev | Tuff Stuff SOP 08.09 |
| Прод меняется осознанно | Сначала read‑only осмотр, изменение только после того, как шаг понят и согласован; одна операция за раз | Tuff Stuff infrastructure.md (правило Andrei 31.08) |
| Реестр сервисов и доступов | Список всех третьих сервисов (Meta, Kommo, BOG, Google, хостинг) с владельцем и местом хранения секрета — без самих секретов; ротация при уходе человека | Tuff Stuff secrets/README, APECS SEC‑002 |

## 3. Данные и сверка (Nichebox Data Platform, Odoo‑опыт EV8)

| Практика | Как в EV8 Ops | Источник |
|---|---|---|
| Сырое хранится как пришло и не переписывается | Строка банковской выписки, вебхук Kommo, вебхук WhatsApp сохраняются raw с датой получения; разбор и сопоставление — отдельный слой, который можно перезапустить | Nichebox G2 «history that never rewrites» |
| Словарь метрик со стабильными ID | «Оплачено по», «долг», «выручка аренды», «залоги на руках» определены один раз с формулой и источником (`M‑nn`), экраны и экспорт считают одинаково | Nichebox §8 Metrics Dictionary |
| Сверка с объяснением построчно | Разница банк ↔ система объясняется строка за строкой (эквайринг, комиссия, депозит, без имени), а не «примерно сходится»; сигнал свежести: «выписка не загружалась N дней» | Nichebox G3, §11 |
| Каждое требование знает метод проверки | FR/NFR несут метод: Test, Demonstration, Inspection, Analysis (IEEE 29148); приёмка этапа — по этим методам | Nichebox §0.4 |
| Отчёт называет, что он заменяет | Каждый экран/экспорт указывает таблицу, чат или Odoo‑вьюху, которую он отменяет; пока замена не подтверждена, старый источник не отключается | Nichebox G5 |
| Данные компании — у компании | Kommo, Meta, банк — интерфейсы поверх нашей базы; выгрузки и история остаются у EV8 при смене любого SaaS | Принцип студии (Nichebox CRM/Braze) |
| Реальные даты событий, не даты внесения | Импорт из Odoo и любые загрузки проставляют дату события; «дата внесения» — отдельное поле | Odoo‑аудит дат 14.08.2026 |

## 4. Безопасность кода (APECS Security Findings, Tuff Stuff auth)

| Практика | Как в EV8 Ops | Источник |
|---|---|---|
| Никакой интерполяции пользовательского ввода в SQL | Только параметризованные запросы Prisma / `$queryRaw` с тегами; raw‑строки с `${q}` — запрещены; проверка grep в CI | APECS SEC‑001 |
| Нет паролей и токенов в репозитории и сидах | Первый владелец создаётся из env при пустой базе; никаких `admin@admin.com`; секреты только в `.env` на сервере; `.env.*` в `.gitignore` | APECS SEC‑002, Self Platform |
| Каждому маршруту — явное право | Guard по роли на каждом маршруте, отсутствие декоратора = ошибка сборки/теста; роли owner / director / manager / mechanic / accountant | APECS SEC‑006 |
| Тонкие клиенты | У web одна публичная переменная — адрес API; секретов и SDK третьих сторон на клиенте нет; CORS allowlist перечисляет стенды | APECS architecture |
| Вебхуки проверяются по подписи | Meta (X‑Hub‑Signature‑256), Kommo (секрет интеграции), BOG (OAuth) — подпись/секрет проверяются до записи; тело сохраняется raw | Tuff Stuff fix `critical-payment-webhook` |
| Персональные данные — по роли и с журналом | Личные номера и документы клиентов доступны только owner/director, доступ пишется в журнал; экспорт бухгалтеру без документов | ТЗ §8, Kultura hr@ (закон о ПД) |
| Одна сборка — один образ | `NEXT_PUBLIC`‑ловушка Kultura: конфигурация читается в runtime из env, а не инлайнится в билд | Kultura ADR‑0009 |

## 5. Дизайн‑система (Tuff Stuff design‑system deep‑dive, бренд EV8)

| Практика | Как в EV8 Ops | Источник |
|---|---|---|
| Один JSON‑источник токенов | `packages/shared/tokens.json` → генерируются `tokens.css`, `tokens.ts`; в компонентах ноль hex‑литералов, проверка grep в CI (у Tuff Stuff нашли 694 литерала против 46 `var()`) | Tuff Stuff 11.09 |
| Токены = бренд с сайта | Значения из `docs/design/brand.md` (ev8.ge), не из головы; тёмная тема как режим тех же токенов | brand.md |
| Стили текста именованы | Набор из ~8 текстовых стилей (Display, H1, H2, Body, Body‑small, Label, Mono, Money), инлайновые размеры запрещены (у Tuff Stuff 676 из 679 текстов переопределяли стиль инлайном) | Tuff Stuff 11.09 |
| Один радиус‑язык | Пилюли 999 px для кнопок и чипов, 16 px карточки, 8 px поля; радиус, которого нет в макете, не появляется в коде | Tuff Stuff (радиус 14 в коде, 0 раз в макетах) |
| Компоненты с состояниями | Button: default / hover / pressed / focus / disabled × accent / outline; Status pill; Money; VIN — как набор Level UP Fundamentals | Tuff Stuff Level UP |
| Страница Foundations в самом приложении | `/design` в web: токены, типографика, компоненты и состояния на живых токенах — ревью дизайна без Figma | Tuff Stuff Studio‑app |
| Шрифты с грузинскими глифами | Noto Sans Georgian в каждом стеке; шрифт без нужных глифов молча падает в системный — проверка в приёмке | brand.md |

## 6. Процесс (студия, APECS, PSP)

| Практика | Как в EV8 Ops | Источник |
|---|---|---|
| Демо после каждого этапа | «Сделано» показывают на тестовом стенде, а не докладывают; Kardu проходит сценарий сам | Weekly 02.09 (APECS Sprint 1) |
| Оценки живут как данные | План этапов и их статусы — в `docs/plan.md` таблицей, из неё собирается отчёт; не в чатах | PSP ADR‑0002 |
| Именование артефактов | Деливераблы (PDF/HTML, экспорты Polaris) — `YYYYMMDDHHMM_EV8_<Name>.<ext>` | ADR‑0003 |
| Решения — в ADR | `docs/adr/NNNN-<slug>.md`, формат Нюгарда, append‑only; решение, которого нет в ADR, не принято | ADR‑0001, книги клиентов |
| Второй читатель для цифр | Контрольные суммы импорта и сверки проверяются вторым проходом (другой скрипт или другая сессия) — у Tuff Stuff второй читатель отменил три числа аудита | Tuff Stuff 14.09 |
